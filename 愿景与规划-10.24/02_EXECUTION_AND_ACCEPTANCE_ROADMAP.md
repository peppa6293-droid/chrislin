## 一、总顺序与不可倒置的原则

`00 愿景与规划留档 → 00B Owner 冻结基线 → 01 只读工程探路 → 02 最小结构快跑 → 03 精准逐项开发 + 随项小测 → 04 整体初步验收 → 05 逐项独立验收 → 06 集成回归/生产安全门禁/Owner 最终裁定`

**顺序解释**：结构快跑主要为了尽早发现架构阻断，不是全面功能验收；精准开发每项完成时的“随项小测”不代替后续独立逐项验收；整体初验先看完整用户旅程，详细验收再核每一条已批准规则。

| 03 逐项精准实施 | 冻结的单项条款+依赖+可复现样本+授权 | 功能按依赖实施；每项即时跑正例、负例、边界和回归子集；失败就小范围返工 | 功能证据包、差异记录、随项小测结果、未完成清单 | 每项具有来源、明确范围、可复现证据；不得自己宣布独立 PASS |
| 04 整体初验 | 功能候选包 | 从首次使用→多格式导入→四盘查看→更正→再次导入→重启做端到端冒烟验收 | E2E 报告、断点、P0/P1/P2 分类 | 可走通核心旅程；不代替逐项深度验收 |
| 05 逐项独立验收 | 冻结需求+已实现源+运行环境+日志 | 不同于执行 Agent 的独立审核逐条运行真实测试，核对源文件、数据、财务结果 | 条款级 PASS/FAIL/BLOCKED/DEFERRED，附可重演依据 | 重要条款逐项闭环，无证据不得 PASS |
| 06 集成回归/交付裁定 | 独立复验结果+正式发布/迁移门禁 | 修复回归，复测跨模块联动，保护已有正式数据，必要时单独走生产升级流程 | 回归总结、遗留风险、Owner 放行包 | Owner 最终确认；生产 Runtime 与数据库迁移分别授权 |

## 三、最低限度的 V3 结构快跑主链

1. 使用匿名/合成账单测试，而非直接导入真实个人敏感历史流水。
2. 文件→来源和文件类型判断→可可靠提取的交易→去重/待确认→一笔唯一真实交易。
3. 根据交易性质更新历史消费分析、确认后的账户关系，并保持**已核对当前余额不被历史补账重复更改**。
4. 消费、现金、资产、债务四盘至少有一条可解释的贯通路径；未知值必须可表示为未知。
5. 重新打开 App 后，仍能回读先前确认状态；支持至少一种异常文件失败而不损坏正常数据。
6. 快跑允许使用暂未覆盖的假数据和模拟接口，但必须清楚标记“模拟、未正式实现、未验收”。

## 四、精准开发建议分组（不是新增功能授权）

- P0 财务正确性：交易性质/分类、跨来源去重、退款、重复现金/债务防护、账本隔离和历史余额保护。
- P1 文件与导入：每一种真实文件结构、异常与恢复、覆盖完整性、安全输入。
- P2 特殊资金链：手续费、跨月退款、外币、分期、组合支付、账户身份、数据来源冲突。
- P3 体验与风险呈现：轻量首次使用、四盘展示、预算提示、批量摘要、友好 UI 与动效。

真正排序必须以第01阶段现有工程结构与测试卡点为依据，再交 Owner 审批，不预先假设全部从零开发。

## 五、记录结构与文件规则

推荐在**真实本地项目根目录**由经授权的 Agent 新建/维护：

```text
docs/product/
  00_FINAL_VISION_AND_CHARTER.md
  01_APPROVED_DECISIONS_REGISTER.md
  02_EXECUTION_AND_ACCEPTANCE_ROADMAP.md
  03_OPEN_QUESTIONS_AND_CONFLICTS.md
  04_OWNER_CHANGELOG.md
  05_TRACEABILITY_MATRIX.md
```

- `00` 固定最终愿景（改动须新 Owner 决议）。
- `01` 记录每一项 Owner 的编号、最后有效方案、批准原文、范围、出处与版本。
- `02` 是执行路线，不等于执行许可。
- `03` 记录未批准、互相冲突、待取证的事项。
- `04` 每次 Owner 决定只增量记录，保留之前版本，不静默篡改。
- `05` 待只读探路后建立“批准条款→源文件→测试→证据→验收结论”的映射。

当前下载包仅在本次会话的工作目录生成，**并未写入用户 Mac 的项目路径**。本地落盘、Git 提交与远端推送都需要独立验证，不能口头宣称已执行。

## 六、职责和会话

1. **规划 Owner 会话（继续当前会话）**：维护愿景、规划和审批台账；不直接宣布独立 PASS。
2. **记录/盘点 Agent（新建，第一次仅有写文档权限或严格只读；授权需明确）**：读取项目原件、将冻结文本按路径保存、复核保存回读和 Git Diff。
3. **结构探路 Agent（新建，只读）**：完整盘点现有架构、数据身份和可运行链路；出证据，不擅自修改。
4. **执行 Agent（之后启用）**：按 Owner 批准的工作包在隔离环境修改，随项提交自测证据。
5. **独立审核 Agent（新建）**：与代码执行者分离，只读验收并形成可复现结论。
6. **Owner**：审批规划基线、每阶段准入、涉及生产/付费/云上传的特别授权，以及最终验收。

## 七、模型与成本（推荐而非授权）

- 愿景和基线审查：GPT-6 High；低成本 GPT-6 Medium。
- 结构快跑/只读探路：GPT-6 Medium 或更低成本执行模型；出现复杂代码/迁移风险升级 Claude Sonnet / GPT-6 High。
- 正式代码执行：优先稳定代码执行模型，按任务长度与成本选；不要使用高价 Opus 承担常规重复性自测。
- 独立财务与迁移审计：GPT-6 High，重大争议可升级 Claude Opus 5.5 High。
- Agent 实际执行提示词中不写模型名称或推理档位；推荐放提示词外。
