最可能失败点：`~/Documents` 的 iCloud 把文件换出（dataless），构建在 `vite transforming` 卡住（M0 已发生两次）。预案：构建脚本第 0 步已含从 git 恢复；仍复发则改到不同步目录构建。

### 步骤 1：查清真机库位置并定数据策略
做什么：用上面两条 `devicectl` 命令取真机库，查看表清单（是否只有 `m0_spike`）。
验收：贴 `files` 列表与 `sqlite3 .tables` 输出；写明真机真实路径。

### 步骤 2：剔除测试代码，并证明不设变量也进不去
做什么：删 `src/lab/`、`src/ui/m0-lab.css`、`src-tauri/tauri.m0lab.conf.json`；`main.tsx` 去掉 M0Lab 导入、样式导入与 `isM0Lab` 分支；清 `v2-tokens.css:75` 起的 spike tokens。保留 `tauri-plugin-notification/haptics` 的注册与 capability（不属于测试页，且 vendored 补丁是 iOS 27 启动所必需）；M1 不提供任何提醒或震动入口。
验收（三条都要有输出证据）：
1. `grep -rE "M0Lab|lab/glass|m0_spike|VITE_M0_LAB|m0-lab" src src-tauri/src src-tauri/*.json web-dist` 为 0 命中（排除 `evidence/`、`docs/`）。
2. 不设变量构建 `build:web` 后，`web-dist` 产物 grep `M0Lab|lab/glass|m0_spike` 为 0（当前 `web-dist` 里 js 命中 2 处、css 命中 1 处，作对照）。
3. 一条自动化测试：把 `window.location.pathname` 设为 `/lab/glass` 并设 `VITE_M0_LAB=1` 后渲染入口，断言渲染的是 `App` 而不是 lab。
最可能失败点：漏删样式或 spike token，或 `web-dist` 仍是旧产物（M0 时旧 dist 导致过一次假 FAIL，见 PROJECT-STATE）。预案：验收前强制重建 dist，并核对产物哈希。

### 步骤 3：首次设置（收入、必要支出、现金、安全目标）
做什么：复用 `Onboarding.tsx` 与 `product-service.completeOnboarding`（`:273`）。界面隐藏资产、债务两块（`Onboarding.tsx` 中这两块默认空数组，提交时传 `[]`），只留收入、必要支出分类、至少一个现金账户、安全目标。
验收：按固定样例输入，保存后进入首页；`calculateMonthlyModel` 的输出与既有测试同一组输入的期望值一致（引用具体测试文件与用例名）；空值、负数、非数字有明确报错且不落库。
最可能失败点：`getOnboardingRequirement`（`product-service.ts:262`）在某些输入下要求 `safetyRecoveryHorizonMonths`，隐藏界面后用户无从填写；`assertUserInputMoney` 对小数位/千分位的拒绝文案。预案：步骤 3 开始先读这两处并写出触发条件，必要时在界面保留该字段而不是改公式。
**需 Owner 决定：** "安全目标"取哪几项。默认取既有三项：`safetyCoverageTargetMonths`（安全覆盖月数）、`minimumCashCoverageMonths`（现金底线月数）、`desiredMonthlyDiscretionarySpending`（期望月可变消费）。

### 步骤 4：记一笔消费（金额、分类、备注、日期）
做什么：复用 `App.recordExpense → services.recordV2CashExpense`（既有保存+回读校验链，`App.tsx:95-120`），入口只开快速记账，不开收入/转账/还款。
验收：保存后读回的金额、日期、分类、备注与输入一致（既有回读校验已覆盖，引用 `quick-entry-flow` 测试）；金额为 0/负/空被拒；日期取设备本地日。
最可能失败点：设备时区。`ui/date.ts` 的 `localDate` 用设备本地时间；M0 时发现过 UTC+8 的 `Schedule.at` 问题。**设备时区目前无证据**（`devicectl device info details` 输出里没有时区字段），记为待验证；用 App 内记一笔、与手机时钟对照的方式取证。

### 步骤 5：首页（本月消费对目标、最近记录）
做什么：用 `HomeApplicationState` 已有字段：`currentMonthSpending`、`recommendedMonthlySpending`/`remainingSpendingCapacity`、`recentExpenses`。隐藏进展、优先行动、导入导出、固定支出、我的财务等入口（`HomeScreen.tsx` 引用了这些页面，只做入口隐藏）。
验收：新增一笔后，「本月消费」与「剩余额度」按共享模型变化，数值与测试期望一致；最近记录按时间倒序显示刚记的那笔。
最可能失败点：`HomeScreen.tsx` 体量大（86 处相关引用），入口耦合多，隐藏时误伤布局或引起空态报错；目标口径选错（`desiredMonthlyDiscretionarySpending` 与 `recommendedMonthlySpending` 不是一回事）。
**需 Owner 决定：** 首页"目标"用哪个。默认用既有首页采用的 `recommendedMonthlySpending`（模型算出的建议月消费），并在界面同时显示用户设定的期望值。

### 步骤 6：重启后数据回读（真机）
做什么：真机装 M1 包，完成首次设置、记 2 笔消费，划掉 App 重开；再次取库文件核对。
验收：重开后直接进首页（不重走首次设置），数据与重启前一致；取出的 sqlite 中 `expenses` 等表行数与界面一致；贴截图与 `devicectl` 取库输出。
最可能失败点：每次重装/换签名会换容器 UUID，数据看似丢失（M1 期间不改签名，可避免）；真机启动时 `ensure_smoke_data_dir_isolated` 因 iOS 的 `home_dir` 与 `app_data_dir` 关系不符而拒绝启动（模拟器通过，真机**待验证**）。
