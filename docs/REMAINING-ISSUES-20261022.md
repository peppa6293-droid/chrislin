- 已更正为三组值：**(a) 生产真数**（债务等，必须一致）／ **(b) 重播目标值**（2026-10-21 户主定案基线，R11 完成后才应出现）／ **(c) 测试夹具**（禁止作验收依据）／ **(d) 已知未接线**（记录不判失败）。并写明**禁止改库凑数**。
- 关键区分：R11 真数重播是把户主真实基线补进库（户主批准的正当数据作业），**不是**为了让任务书数字对上而改库凑数——两者动机与数据来源完全不同，不得混为一谈。

**F5.（2026-10-22 R11 阻塞暴露，审核员代码审计属实）V2 收入无生产写入口**
- 现状：`recordIncomeEntry`（→ `income_entries`）服务函数存在但**全仓零调用者**；生产界面「新增收入」写的是 V1 `income_records`（另一套表），仪表盘收入只读 `income_entries`（`src/application/v2-expense-service.ts:373`）。故 2026-09 工资 12,791.25 + 进步奖 1,000 在冻结包里**无合规途径入库**，仪表盘「收入」恒 0.00。
- 关联机制：直接 SQL 写库会触发启动门闸内容校验失败（见 E3/R11 回执），所以这不是「找个 SQL 路径」能绕的——只能补界面。
- 处置：V0.2 增加 V2 收入录入入口（须能选归属月份或按发生日归属；口径未定会导致跨月补录永不可见）。补界面后走应用写路径把真数补进。
- 验收影响：A01 §2(b) 的收入/经常性收入目标值暂不可达，读到 0 是预期现状。

**F6.（同上）V2 固定支出计划无生产写入口**
- 现状：`createFixedExpensePlan`（→ `fixed_expense_plans`）零调用者。仪表盘「固定支出 / 核心义务」只读该表（`src/application/v2-expense-service.ts:429`），恒 0。
- 影响：房租 1,900/电池 728/停车 300/饮食 1,500/车险预提 648.31（合计 5,076.31）与 2026-11 核心义务 13,927.34 无法显示。
- 处置：V0.2 增加固定支出计划管理入口，补数走应用写路径。
- 验收影响：A01 §2(b) 固定计划/核心义务暂不可达，读到 0 是预期现状。

**F7.（同上）账户预留额无生产写入口**
- 现状：`setCashAccountReservedAmount`（→ `cash_accounts.reserved_amount`）零调用者；财务维护界面的账户表单没有预留额字段。
- 影响：农行预留 3,800.00（房租专款并入）无法如实表示 → 「预留 0.00 / 自由现金 25,325.93」，自由现金**虚高 3,800**，安全判断会偏乐观。
- 处置：V0.2 账户编辑增加「预留金额」字段，补数走应用写路径。
- 验收影响：A01 §2(b) 预留/自由现金暂不可达；**此项对用户决策有实际误导性，建议排 F5–F7 最优先**。

**F8.（R12 转换阶段发现，2026-10-22 代码+库实证）V2 账户表（`accounts`）无管理入口**
- 现状：`createAccount`（`src/persistence/repositories.ts:1548`）仅被开机自举调用（`src/runtime/tauri-bootstrap.ts:212`），生产界面无新增/编辑 V2 账户入口；生产库 `accounts` 表只有一行「现金」。「余额宝/微信零钱/农业银行」等只在旧现金账户表（`cash_accounts`）里，导入界面账户下拉（`src/ui/v2-import.tsx` 读 `context.accounts`）永远只显示「现金」。
- 影响：记账/导入的「从哪个账户出」无法细分——R12 的 824 笔导入已按审核员裁决统一落「现金」（真实付款方式留对照表）；日后用户想按账户分账也做不了。
