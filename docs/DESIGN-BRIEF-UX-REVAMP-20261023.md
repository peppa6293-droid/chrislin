## 0. 背景（为什么找你）

小钱家是本地优先的个人财务桌面 App（Tauri + React + TypeScript，macOS 主力）。户主真实试用后的核心批评：**界面是数字表堆砌，枯燥、看不懂、low；记账没有反馈感**。户主明确指定了质感标杆：

> **多邻国（Duolingo）风格**——完成一个动作要有庆祝动画、进度点亮、连击感；表达像做 PPT 一样图文优先，绝不把一堆数字甩用户脸上。

实现由执行者负责，但**审美决策权在你**：配色、圆角、字体层级、间距、图标风格、动效时长与曲线、组件状态、页面构图，全部由你定稿。执行者将逐条照你的稿实现。

## 1. 你的任务

产出一份**可直接落地实现的设计稿**：`docs/DESIGN-UX-REVAMP-20261023.md`。不是设计散文、不是形容词建议——是实现方拿来照抄的规格书。

## 2. 设计范围（六个表面）

1. **首页两卡**（核心）：
   - 结构卡（长期）：收入 − 固定支出 − 月供 = 结构余量，一眼看懂「长期格局，不用每月盯」；
   - 本月消费卡（短期）：已花 vs 目标，动画进度条，超支有明显状态变化。
2. **记账反馈三件套**（户主最在意）：
   - 记完一笔：庆祝动画（元素、节奏、时长你定，参考多邻国答题正确的量级感）；
   - 记完一天：完成感（可含连续天数/连击元素）；
   - 记完一月：月度小结庆祝页（PPT 式图文小结，不是数字报表）。
3. **日历式日期选择器**：大尺寸、可点选，替换现在的原生小输入框；只要日期不要时间。
4. **「建立余地」新页面**：储蓄/余地目标的图文进度页（目前该入口是坏的，跳去了安全垫页；页名可由你起）。
5. **详情页图文化模板**：现有安全垫页 13 行数字像论文。每页只回答一个问题（「安全垫够不够？」「这个月要还多少？」），结论先行 + 进度条表达目标 vs 现状，算法说明收进可展开层。至少覆盖：现金流、安全垫、债务还款三个详情页的模板与各自构图。
6. **全局视觉语言**：design tokens（颜色/圆角/字阶/间距/阴影）、金额排版样式（¥、千分位、大小层级）、图标风格（现用 lucide 图标，换风格或保留由你定）、通用组件（卡片、按钮、进度条、空态、徽章）。

**本期只给规范不精稿的页面**：还款记账、固定支出维护、导入确认等功能页——由 tokens + 通用组件覆盖；如你认为其中某页需要精稿（例如还款页），可加一节给出。

## 3. 硬约束（违者稿不算数）

1. **视觉方向：多邻国式圆润明快。禁止像素风**——项目里有历史像素风死代码（PixelWorld 等），仅作反面参考，不得照搬。
2. **桌面端 macOS 窗口**，不是手机 App；但气质是亲和的消费级产品，不是金融报表工具。考虑窗口宽度下的信息密度。
3. **必须给可落 CSS 的数值**：色值（hex）、圆角（px）、字号（px/weight）、间距、阴影、动效时长（ms）与缓动（cubic-bezier）。每个组件给出**状态表**：默认/按下/完成/超支/禁用/空态。不许只写「活泼一点」。
4. **必须给 reduced-motion 降级方案**（系统减弱动效时静态但仍有完成感）。
5. **不改数据口径与功能范围**：数字怎么算、有哪些功能已由 `docs/UX-REVAMP-PLAN-20261023.md` 与执行任务书定稿，你负责它们的**视觉表达**；发现口径影响表达时，在稿中「备注」提出，不擅自改。
6. 中文界面。文案基调：说人话、短句。可在稿中给关键文案建议（户主可再调）。
7. 现有技术栈落地：React + 现有 CSS 体系（`v2-*` 命名空间）+ lucide-react。稿中注明哪些复用现有组件、哪些新建。

## 4. 产出物规格（`docs/DESIGN-UX-REVAMP-20261023.md` 必含）

1. **设计原则**一页：风格定位 + 明确「不做什么」；
2. **Design tokens 全表**：语义色（正常/超支/庆祝/中性/危险）、圆角、字阶、间距、阴影、动效时长档位；
3. **六个表面逐节**：布局构图（文字线框/ASCII 即可）+ 组件状态表 + 动效规格（触发条件/时长/曲线/元素变换）；
4. **动画专项**：记一笔庆祝、日完成、月度小结页、进度条增长——每条给触发/时长/曲线/元素；
5. **reduced-motion 降级**逐条对照；
6. **落地备注**：复用/新建组件清单、实现顺序建议（哪些先做视觉收益最大）。

## 5. 范围外

- 不写实现代码（实现归执行者）；
- 不改双账本契约、财务模型、导入导出逻辑；
- 不做 App 图标/品牌全案（另有任务）。

## 6. 验收（设计稿是否合格）

执行方与户主按此检查：① 每个表面能否**不问你任何问题**直接实现；② 动效是否有精确时长与曲线；③ 是否多邻国质感而非像素风；④ reduced-motion 是否覆盖；⑤ 数值是否全部可落 CSS。
