## 3. 问题清单（按严重度）

### 3.1 高 — 「建议别超过 ¥0.00」与安抚文案自相矛盾
进展页实测：已花 ¥9,372.42、目标 ¥1,600、超出 ¥7,772.42、**建议别超过 ¥0.00**，下方却写「这个数字只是帮你做参考，不会限制你记录已经发生的花销」。超支后建议上限塌缩为 0，读起来像惩罚而非参考，直接抵消安抚语义。
建议：超支时该行改为「已超出目标 ¥X，剩余可花为 0」或隐藏该行，别让 0 冒充「建议」。

### 3.2 高 — 记账闭环缺三类真实动作：转账、还款、资产变动
现金在账户间挪、给信用卡还款、资产估值变化，都是「本地账本」用户的日常，当前 `expenses.kind` 只有消费三类。缺它们时，现金卡余额与流水对不上，用户只能靠月度维护弹窗手工纠偏——这正是「更新财务数据」弹窗存在的原因，属于用维护补丁替代记账原语。
建议：`expenses.kind` 增 `TRANSFER` / `REPAYMENT`（还款联动 `debts` 与 `cash_accounts`），资产维护给独立入口；schema 加列即可，不必新表。

### 3.3 中 — 无任何提醒能力
全仓无通知代码。「今天」页依赖用户主动打开；streak（`getRecordingStreak`）已有后端却没有可见的前端激励，也没有「今晚记一笔」类提醒承接。
建议：先做 in-app 提醒（今天页空状态 + 晚间未记提示），系统级通知延后到移动端。

### 3.4 中 — 我的财务页职责混杂
同一页塞了：仪表盘（四卡）、设置区（三个按钮）、综合维护入口（三条长链接）、任务卡（第 1 步）。四卡本身已是良好摘要，但下方两区使页面长度和认知负担翻倍。
建议：四卡保留为页主体；「高级维护 / 设置安全目标 / 数据与隐私」与「收支账本 / 财务概览 / 账单导入」合并为一个「维护与工具」分组列表；任务卡仅在未完成 onboarding 时出现。

### 3.5 低 — 重复标题与入口冗余
进展页 H1「这个月花了多少」与卡片内标题重复；顶栏「记一笔」与记录页「记下今天的花销」、今天页「刚刚发生」三处入口指向同一动作，文案各异。
建议：统一为「记一笔」一个动词；卡片标题删一层。

### 3.6 低 — schema V8 功能疑似悬空
`fixed_expense_plans`、`income_entries.one_time`、`reserved_amount` 已入库，但实测维护弹窗只暴露「稳定月收入 + 必要支出 + 现金账户」。若 V8 字段无 UI 消费，属于死重量；若有 UI 未在探索路径到达，需补验证。
建议：下一轮迭代先核对这三者的读写方，再决定接线或回滚。

## 4. 保留 / 合并 / 增强 / 新增

**保留（实测有效，别动）**
- 四页主导航与信息架构骨架
- 「保持轻盈 / 本地记录」的定位文案与语气
- 3–5 秒快捷记账、刚刚发生流
- 环形图 + 最近花销 + 目标对比的进展页主体
- 更新财务数据弹窗（月度维护心智清晰）
- 导入去重（`dedupe_key`）与本地商家关键词分类（无网络、隐私一致）
- 导出备份（JSON + CSV 双份）

**合并**
- 我的财务页两个设置区 → 一个「维护与工具」列表（§3.4）
- 三处记账入口文案 → 统一「记一笔」（§3.5）
- 「高级维护」与「更新财务数据」弹窗若功能重叠，收敛为一个月度维护流程

**增强（已有底子，补最后一公里）**
- 超支文案与「建议别超过」逻辑（§3.1）
- streak：把 `getRecordingStreak` 接到今天/进展页可见处
- 财务概览、设置安全目标、数据与隐私：本轮未到达的三个页面，下轮优先实测
- 导入审查界面暴露商家自动分类建议，允许一键采纳/改

**新增（按优先级）**
1. 转账 + 还款记账原语（§3.2）——闭环缺口，最高优先
2. in-app 未记提醒（§3.3）
3. 资产估值维护入口（表已有，缺 UI）
4. 债务还清时间线（基于现有 `debts`/`debt_period_facts` 计算，纯展示层）
5. 子分类、多账本：明确不做或推迟——单用户本地 app 收益低、复杂度高
