## 1. 大白话结论

### 1.1 可以保留的部分

参考资产的整体方向可以保留，不需要推倒重来。以下内容已经有足够证据作为**设计基线**：

- 五档结构余量梗文案及两种零收入文案逐字保留；
- 固定支出标题使用「固定支出·{实际数量}项」；
- 空态使用「固定支出·0项」和「暂无固定支出」；
- 删除固定支出页独立提示行；
- 已付行隐藏「再记一笔」；
- 未付行使用「记一笔」；
- 付款面板从底部弹出；日期和备注作为同一组整体展开/收起；默认收起；保留「取消」；提交按钮为「确认付款」；
- 已付进度使用细线，未付使用普通灰色背景；不恢复旧虚线方案；
- 骨架屏不显示加载文案；局部错误文案为「这一块没读出来，点这里重试」；
- Apple 原生感作为视觉方向；不新增依赖、第二套 Token 或第二套图标库。

以上是**设计基线通过**，不是产品实现通过，也不是业务逻辑验收通过。

### 1.2 不能直接交开发的部分

当前参考图把部分未决候选画得过于接近定稿，容易让执行方误把候选当成正式规则：

1. 双环把“固定负担÷收入”和“消费÷预算”并列在同一个收入中心旁，分母不同但视觉上没有充分说明；
2. 超载仍使用醒目的红色斜纹弧，最终超载画法尚未由 Owner 签认；
3. 零收入保留双环、显示 ¥0 和实际负担且不显示百分比已明确，但双环轨道仍容易产生“有进度”的误读；
4. 主卡、环形卡和模块右上角存在重复的超出信息，需要明确哪些必须保留、哪些只做低层级辅助；
5. 参考画布使用 1120px 内容宽度，不能直接代替正式页面的 980px `finance-page` 和 800px `detail-page`；
6. 本月/上月、分类点击、真实跨月、真实保存与重复支付没有得到真实业务证据。

### 1.3 已发现且必须修正的参考资产缺陷

以下不是审美偏好，而是可复现缺陷或验收缺口：

- **F-01 付款摘要未更新：** 修改日期/备注后收起，摘要仍显示占位提示；再次展开值仍保留。应在参考返工或实现任务中要求摘要显示实际值。
- **F-02 折叠控件无障碍关联错误：** `aria-controls` 指向空节点，未指向实际共同字段容器。需修正 DOM 关联并重新核对键盘/读屏行为。
- **F-03 图形对比度不足：** 部分品牌色环、灰轨和分类填充低于项目要求的图形 3:1 下限。保留品牌色方向，但必须通过边界线或同色深阶修正并复测。
- **F-04 固定支出摘要环缺少清晰可见名称：** 当前主要显示百分比，普通视觉用户不易确认其含义。若继续保留 #12，应显示已确认口径「本月已付占比」；不得凭空增加新标题。
- **F-05 手机首屏偏长：** 390×844 正常态中首个模块约在 y=1003 才出现；应压缩无效留白和重复层级，不得靠缩小正文或删除 Owner 要求的信息。
- **F-06 短视口操作区需补证：** 390×520 下确认按钮初始不完整可见，滚动后可操作；尚不能宣称已覆盖真机软键盘、日期弹层和动态字体。
- **F-07 旧 `renders/` 与新资产混存：** 旧版大装饰环、旧裁切和旧状态选择器容易被单图误用。交接时必须明确旧资产非验收基线，或隔离/标注。

参考资产返工只允许在另行获得 Owner 授权后进行；本任务书不授权返工。

### 2.1 D-01/#1 逐字文案

- 结构余量比例 ≥20%：「账单：不是，他怎么还剩钱？」
- 结构余量比例 >0%、<20%：「钱包：还活着，先别开香槟。」
- 结构余量比例 =0%：「工资：来过，爱过，没留过。」
- 结构余量比例 >−10%、<0%：「工资：你们分赃怎么不带我商量？」
- 结构余量比例 ≤−10%：「收入：我一个人打五个？」
- 收入为 0 且已知固定负担为 0：「收入：你不来？账单：那我也不来了。」
- 收入为 0 且已知固定负担大于 0：「收入：暂未出场。账单：戏份拉满。」

上述文案进入正式实现时须作为已确认新增槽位登记，不得伪称为现网原文。

## 3. Owner 必须补齐的六组阻断项

以下 B-01～B-06 是当前进入完整 P1–P4 执行任务书前的阻断项。设计建议只能作为候选，不自动成为规则。

### B-01｜双环的准确数据口径

请确认圆环本身的组成：

- **A：** `固定支出 + 必须偿还月供 + 非负结构余量 = 月收入`；
- **B：** 仅表示固定支出/必须偿还月供的分类构成；
- **C：** 其他：________。

并补充：

1. 固定支出与必须偿还月供是否分别成段；
2. 分类卡是否与圆环分段一一对应；
3. 圆环中心是否始终显示所选月份月收入；
4. 结构余量为负时是否有独立视觉表达；
5. 消费进度是否移出圆环、留在消费模块，或继续作为独立环但明确分母。

**审美设计师建议（非默认答案）：** 优先考虑两环使用同一收入基准，分别表示固定支出和必须偿还月供；消费进度留在消费模块。若保留消费÷预算，必须在图例中明确分母，不得继续只写百分比。

### B-02｜圆环特殊状态

请分别确认：

- **零收入：** 已确认显示 `¥0` 和实际负担、不显示百分比；请确认双环是保留为“不可计算轨道”，还是不绘制进度弧；
- **固定负担=收入：** 是否整环为负担、余量为 0；临界色和标签是什么；
- **固定负担>收入：** 超出部分如何绘制；是否使用短实色端段、斜纹或其他方式；超过一圈如何表达；白线、超出段和金额如何排列；
- **待确认债务：** 是否阻断圆环/评级；确认前禁止使用旧快照显示金额或比例。

硬性标准：不得除零、截断、归一化或缩放实际超支；不得把超载显示成正常 100%。

**审美设计师建议（非默认答案）：** 超载优先“金额和负余量清楚、纹理弱化”，可考虑短实色超额端段；红色不铺满整卡；斜纹不可默认冻结。

### B-03｜固定支出分类进度边界

请确认：

1. 计划>0、已付=0：进度为 0，标签是否只显示「未付」；
2. 已付>计划：进度线是否可超过 100%；超额如何标识；实际已付和超额金额是否同时保留；
3. 计划=0、已付>0：不得计算普通百分比，使用何种文案/标记；
4. 已付金额不得静默截断、归一化或改写为计划金额。

### B-04｜负收入归属

请选择：

- **A：** 业务上不可能，输入层阻止并进入错误态；
- **B：** 独立异常状态，补逐字文案和视觉规则；
- **C：** 沿用零收入处理；
- **D：** 其他：________。

若选 B/D，必须补文案、圆环规则、百分比规则及验收证据。

### B-05｜本月/上月切换

请确认切换后是否全部按所选月份重新计算：

- 标题和结论句；
- 圆环中心收入；
- 固定支出、月供和分类金额；
- 已付/计划比例；
- 待确认债务状态；
- 超载金额与边界色。

并确认数据不完整、缓存过期、切换中断时的显示规则。不得沿用本月数据、旧首页快照或静默补值。

### B-06｜动效、图标和无障碍规格

请补齐以下最小规格：

**动效：**

- 展开/收起、条形生长、数字变化、图标反馈分别用于哪些组件；
- 首次进入、用户操作、数据更新分别何时触发；
- 各动效时长、缓动方式；
- 取消、错误、重复点击和中断时的处理；
- `prefers-reduced-motion` 下关闭还是降级。

**图标：**

- 类型和位置；
- 尺寸、有效绘制区域、描边/填充、颜色和底托；
- 正常、已付、未付、错误、展开/收起、空态状态；
- 文本替代、键盘焦点、非颜色识别规则；
- 是否继续使用现有项目图标体系，不引入新库。

**注意：**“Apple 原生风格”是方向，不是可直接验收的实现规格；原型中的 220ms、旧 24px/1.7px SVG 也不能自动视为最终规格。

## 4. 整合后的验收标准

### 4.1 业务与视觉规则

- 五档及零收入文案逐字一致；
- 圆环每一段有明确分子、分母、月份和标签；
- 零收入不出现百分比；
- 临界、超载、待确认债务均有明确且可复现的画法；
- 超载真实金额、负余量和超额范围不被截断或归一化；
- 分类 0%、超付、计划为 0 均有明确规则；
- 本月/上月切换不得串用数据或旧快照。

### 4.2 页面与响应式

- 以正式页面实际容器为准：`finance-page` 980px，`detail-page` 800px；1120px 参考画布只能作为展示稿；
- 验收宽度：760、980/1000、1440；
- 760–880 面板按既有窄断点降级，1000 单列，1440 双列；
- 不出现横向溢出、底部导航永久遮挡或关键操作不可达；
- 手机短视口、软键盘、日期弹层和动态字体需独立证据，不能用长截图代替。

### 4.3 可访问性与视觉质量

- 图形元素满足项目要求的 3:1 对比度；
- 颜色不是唯一状态表达；
- 折叠控件控制真实字段容器，键盘和读屏关系正确；
- reduced-motion 规则可验证；
- 文案、金额、日期、比例中不得出现“示例数据/演示/占位”或设计注释；
- 设计资产中的旧稿、候选稿和审核标记不得被误当成正式基线。

### 4.4 证据要求

- 证据统一放入 `evidence/wp-ui-visual-01/`，不得使用 `/tmp` 作为交付目录；
- 每个状态提供截图、源文件、复现命令和断言；
- 至少覆盖正常、零收入、临界、超载、待确认债务、空态、加载、局部错误、已付、未付、超付和计划为 0；
- 真实付款、跨月、持久化、重复支付和生产环境不属于本任务书已通过范围，需另立业务验收。
