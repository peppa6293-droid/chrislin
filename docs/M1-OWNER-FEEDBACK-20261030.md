## 我查到的事实

### 第 1、4 条：输入时页面放大（同一个问题）
- 这是我上一轮"平台修复"本来要解决的问题，Owner 现在仍然遇到，所以**不能算已修好**。
- 已核实：构建产物 `web-dist` 的 CSS 里确实有"触屏设备上输入框 16px"的规则（`@media (pointer:coarse)`，覆盖全局 `input, select, textarea`），并且排在原来 14px 规则之后。金额输入框 26px，日期按钮 16px，也都不小于 16px。
- **没核实：** 我没法确认这条规则在手机上是否真的生效。可能原因我只能列出，不能断定：
  1. `(pointer: coarse)` 在这个 WebView 里没有匹配；
  2. Owner 测的是修复前的包（我 13:51 才装上新包，第一次启动还因锁屏失败过一次）；
  3. 放大不是由字号引起，而是别的原因（例如弹层固定定位与键盘弹出的相互作用）；
  4. 装进手机的包与我检查的 `web-dist` 不是同一份（我在 IPA 里找不到明文 CSS，Tauri 把资源打进了二进制，所以**无法直接核对手机里的实际 CSS**）。
- 我没有手机截图、没有 Safari 远程检查器，所以**我现在无法复现**，也不知道缩放比例。

### 第 2 条：首页顶部
- 事实：顶部栏是 `position: sticky; top: 0`，所以向下滚动时它一直钉在屏幕上方，占 64px 外加状态栏安全区。
- **我对这句话有两种读法，没法确定：**
  - A：顶部栏一直钉住占着地方，不像 iOS 原生那样随内容滚走或折叠成大标题；
  - B：下拉时整个页面（含顶部栏）一起橡皮筋式晃动。
- 这条需要 Owner 回答是哪一种，我不替你猜。

### 第 3 条：左滑返回
- 事实：App 里没有任何历史记录或手势代码（搜索 `history.`、`popstate`、`pushState`、触摸手势，结果为空）。M1 首页只有一个页面，首次设置有"上一步"按钮、记账弹层有"关闭"按钮，但都不响应左滑。
- 没核实：原生 WebView 的"边缘滑动返回"是否被开启，我没有在原生配置里找到相关设置。
- 要先决定：左滑在哪里该生效（首次设置回上一步？关闭记账弹层？）。这是交互设计，属于需要你审批的对象，不是平台小修。

### 第 5 条：记账成功动画
- **我在当前代码里找不到你描述的东西。** M1 首页保存成功后只做三件事：弹层关闭、最近记录里新增那一行做 420 毫秒插入动画、金额数字做 760 毫秒强调。**没有任何需要手动关掉的层。**
- 你描述的"多且长、要手动关掉"很像旧完整首页里的：庆祝反馈舞台（`V2FeedbackStage`）、"今天已记完"层（`V2DayComplete`）、月度小结（`V2MonthSummary`）。这些我在 M1 首页里没有带。
- 所以有两种可能：你在说昨天看到的旧版体验；或者你在手机上确实看到了我没找到的东西。**请你确认是哪一种。**

## 我这边承认的失误
- 我上一轮把"输入框放大"当成已解决汇报，依据只是构建产物里有 16px 规则，没有真机验证，却写成"平台修复做完了"。这个说法过早，应该写成"规则已进包，是否生效待真机验证"。
