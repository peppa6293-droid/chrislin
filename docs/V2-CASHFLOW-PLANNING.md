# V2 信用卡账单与现金流压力规划（隔离候选）

## 范围

本文件对应 `EXEC-L-04`，仅覆盖隔离 V2、synthetic fixtures、Decimal 计算和 mock 场景。它不是 Production 功能、不是正式发布说明，也不代表项目验收完成。

## 口径

- `amountDue`：账单出账时确认的本期应还金额。
- `paidAmount`：账单上已登记的实际还款之和。
- `remainingAmount`：`amountDue - paidAmount`，只能为零或正数。
- 信用卡消费属于消费确认；实际还款属于现金结算，不能再次增加日常支出。
- 现金压力只描述未来或当前还款对可用现金的影响，不把未来应还金额伪装成已经发生的现金支出。

## 周期规则

`createBillingCycle` 使用账单月份、账单日和到期日创建周期：

- 周期起点是上一个账单日的次日；
- 周期终点和出账日是本期账单日；
- 到期日早于或等于账单日时，自动落在下一个月；
- 31 日在没有 31 日的月份按该月最后一天处理；
- 所有日期均使用严格的 `YYYY-MM-DD` 校验，并用 UTC 计算避免本地时区漂移。

## 压力状态

- `NONE`：已还清；
- `UPCOMING`：尚未还清，但当前可用现金可以覆盖剩余应还；
- `SHORTFALL`：尚未到期，但当前可用现金不足以覆盖剩余应还；
- `OVERDUE`：已超过到期日且仍有剩余应还。

输出同时包含普通用户可理解的中文说明，不使用未定义的金融术语。

## Synthetic 验证覆盖

专项测试覆盖：正常周期、跨月、跨年、部分还款、多次还款、已还清、零剩余、现金不足、逾期风险、到期日边界、非法月份、非法金额、非法日期、还款超额和现金不足以完成结算。

## 边界

- 不连接真实信用卡、银行、支付宝或微信；
- 不写入 Production App/DB；
- 不修改 Financial Model V1.0；
- 不实现 L-05 储蓄目标；
- 不实现 U-03 综合 UI；
- `projectCashAfterBillPayment` 只计算剩余账单结算后的现金余额，不执行真实扣款。
