# 小钱家 V2 产品与视觉设计

状态：`DESIGN_READY_FOR_MUSE_EXECUTION`
日期：2026-10-14（Asia/Shanghai）
目标平台：macOS + iPhone/iOS，最终准备 App Store 发布

## 1. 这次重做要解决什么

当前候选包 `/Users/linte/Documents/ChatGPT/个人财务模型app开发项目 2/artifacts/wp03-isolated-product-preview-20261012/build-09/cargo-target/release/bundle/macos/小钱家 WP-03 测试版.app` 已经有财务模型、记账、收入、现金、资产、债务和安全垫能力，但产品层仍像一个财务控制台外面叠了一层任务组件。

真实界面核对到的主要问题：

- “今天的任务”、财务四模块、我的财务、维护入口同时争夺首页注意力，没有唯一主循环。
- 多邻国式任务感停留在标题、奖励条和 CSS 角色，没有成为产品导航和反馈系统。
- 首页数据层级不稳定；用户无法在第一眼明确知道“今天做什么、做完有什么变化”。
- 测试版的“试用日期”入口出现在可见产品界面，不得进入正式发布版。
- 维护、历史和模型解释入口像旧控制台遗留入口，应被重新组织，而不是继续堆在首页底部。
- 现有测试候选显示过不合理的目标数据（例如安全目标被渲染成 10,000 个月）；正式 UI 必须对异常/极端值保持可读，并禁止测试夹具污染正式演示状态。

## 2. 产品定位

小钱家不是记账表格，也不是投资建议工具。它是一个“每天花几秒钟照顾自己的钱”的本地优先财务陪伴 App：

1. 让用户快速记下一笔实际消费。
2. 用一句人话告诉用户本月状态发生了什么变化。
3. 每天只给一个最值得做的小步骤。
4. 用连续完成、进度和里程碑形成长期习惯，但不把财务行为变成虚假积分游戏。

核心循环：`打开今天 → 完成一个小步骤 → 立即看到结果变化 → 选择离开或继续`。

“多邻国风格”只借鉴以下产品原则，不复制其品牌、角色、图形、文案或页面：

- 明确的今日任务。
- 轻量、分步、可完成的路径。
- 完成后的即时正反馈。
- 可选的连续记录，不惩罚中断。
- 友好但不幼稚的角色语气。

## 3. 信息架构

### iPhone 主导航

使用 4 个底部 Tab，始终可见，图标配短文字：

1. `今天`：每日主循环、月度摘要、一个优先行动。
2. `记录`：快速记录消费，也可查看最近记录。
3. `进展`：消费、安全垫、债务、资产的进度路径。
4. `我的`：收入、现金、资产、债务、安全目标、设置和数据管理。

不要再使用“今天 / 财务 / 设置”这种三个按钮的临时导航，也不要把“更新财务数据”作为首页主要 CTA。

### macOS 主导航

使用左侧窄栏，复用同一套 4 个目的地。窗口宽度变化只改变内容布局，不改变信息架构：

- 640–799px：窄栏 + 单列内容。
- 800–1199px：窄栏 + 720–880px 主内容。
- 1200px 以上：主内容左对齐，右侧可显示解释/最近活动，但不增加第二套导航。

macOS 顶部固定一个 `记一笔` 主按钮；iPhone 在 `记录` Tab 中使用同一入口。

## 4. 关键页面设计

### 4.1 首次设置：一问一屏

目标完成时间 2–3 分钟。每一步只问一个主题，顶部显示 `第 n 步 / 5` 和稳定进度条。

步骤：

1. `收入`：稳定月收入。
2. `生活`：必要生活支出，允许先输入总额，细分项放在“稍后完善”。
3. `手头`：当前现金、可计入安全资源的资产。
4. `责任`：债务和本月还款事实；缺少本月事实时明确显示“待确认”，不能用旧值伪装成当前值。
5. `目标`：安全垫目标、现金安全线、期望月度可变消费。

每一步都提供：

- 一个主输入区。
- 一句短解释，说明这个值会影响什么。
- `下一步` 主按钮和 `稍后完善` 次按钮（仅在业务允许时）。
- 返回不丢失输入。

不要在 onboarding 中展示复杂表格、专业术语、四个并列卡片或完整模型公式。

### 4.2 今天：首页唯一主循环

首页从上到下固定为 5 个层级：

1. 顶部：品牌、当前月份、设置图标；macOS 另有窗口标题栏。
2. 今日任务：一个主任务卡，只出现一个主要 CTA。
3. 即时结果：本月已花 / 目标、计划收入 / 核心支出 / 剩余、安全垫覆盖、债务待确认状态。
4. 本月进度：一条横向或纵向路径，最多 4 个里程碑。
5. 最近记录：最近 3 笔消费和“查看全部”。

今日任务根据现有确定性模型选择，不新增业务判断：

- 结构性缺口：`先把本月收支缺口理清`。
- 现金安全线未达：`先让手里的现金安心一点`。
- 主要拖累是消费：`记下一笔今天的花销`。
- 债务本月事实缺失：`确认本月要还多少`。
- 安全垫有缺口但无硬闸门：`看看安全垫离目标还有多远`。
- 没有明确问题：`记下一笔今天的花销`，不制造焦虑。

每次只显示一个任务。任务卡必须包含：标题、为什么现在出现、预计耗时、主按钮、完成状态。不要同时放 5 个任务列表。

完成任务后的反馈：

- 任务按钮变成已完成状态。
- 相关财务数字立即刷新。
- 显示一条轻量反馈，例如“已记入本月消费，本月还剩 ¥X”。
- 连续记录只作为小字状态，不使用强制弹窗、不发出庆祝音效、不阻断后续操作。

### 4.3 记录：3–5 秒完成

打开方式：底部 `记录` Tab、macOS 顶部 `记一笔`、首页任务卡。

顺序必须是：

1. 金额输入自动聚焦；iPhone 使用数字键盘。
2. 类别为可选图标行：餐饮、交通、购物、娱乐、日用、其他。
3. 备注为可选。
4. 日期和时间自动产生；保留用户本地 `business_date` 语义。
5. 保存后立即回到当前上下文，并更新首页/记录页。

金额错误必须保留输入并明确说明原因。保存失败不能显示成功反馈。

### 4.4 进展：把模型翻译成路径

进展页不是 KPI 仪表盘，不显示 0–100 健康分，不使用跨量纲综合分。

用一条纵向“照顾路径”展示 4 个维度：

- `看清消费`：本月已花、个人目标、剩余或超出。
- `稳住现金`：现金安全线、现金覆盖、当前状态。
- `理清责任`：总债务、本月应还、待确认项。
- `建立余地`：安全垫覆盖、目标、缺口。

每个节点显示当前值、变化方向和一条解释。点击进入详情。路径视觉上有完成感，但不能把未达目标涂成失败或红色惩罚。

### 4.5 我的：事实维护与设置

分组列表，不做四张大插画卡：

- 收入：稳定月收入、本月计划收入、实际收入。
- 现金：账户和可计入安全资源的资格。
- 资产：资产余额、流动性和安全资源资格。
- 债务：余额、本月事实、停用历史。
- 安全目标：安全垫目标、最低现金线、恢复周期、期望可变消费。
- 数据与隐私：本地存储说明、导出/导入（只有实际实现后显示）、关于。

每个编辑流程都必须保存后重新读取，再刷新相关页面。不要把 derived result 写回成事实。

## 5. 视觉系统

### 5.1 气质

关键词：`友好、清楚、有节奏、轻触感、成年人可长期使用`。

不要做成：儿童游戏、金融 SaaS 仪表盘、米色生活方式博客、单色绿色模板、复制多邻国视觉。

### 5.2 颜色

使用实色，不使用背景渐变、发光球、bokeh 或装饰性渐变。

```text
--ink: #18212B
--muted: #66717D
--paper: #FFFDF7
--surface: #FFFFFF
--line: #E7E9E5
--teal: #129B84
--teal-dark: #087662
--coral: #F06A58
--blue: #5272D8
--yellow: #E7AD35
--lavender: #8472C7
--danger: #C94F58
```

Teal 负责主行动，coral / blue / yellow / lavender 只用于维度区分。任何状态都必须同时有文字或图标，不能只靠颜色。

### 5.3 排版和尺寸

- 优先使用系统字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Noto Sans SC", sans-serif`。
- 正文 14–16px；辅助文字不小于 12px。
- 金额使用等宽数字或稳定数字宽度，避免刷新时跳动。
- 不使用负字距，不使用随视口缩放字体。
- 页面区块间距 24–32px；单列内容宽度 680–880px。
- 卡片圆角最多 8px；输入和主要按钮可用 8–12px，避免大量胶囊形容器。
- 主 CTA 有图标和文字；纯图标按钮必须有 tooltip/aria-label。

### 5.4 插画、角色、动效

- 角色只保留一个“小钱家”陪伴角色，三种状态：默认、完成、需要注意。
- 角色不得出现在每一块财务数据旁边；每天最多在今日任务卡出现一次。
- 优先使用真正的 bitmap/vector asset，不用大量 CSS 拼脸作为最终品牌资产。
- 动效只用于：页面切换、数字变化、任务完成、进度节点点亮。
- 单次动效 150–350ms；支持 `prefers-reduced-motion`。
- 不使用自动循环的大面积动画，不用音效作为完成条件。

## 6. 数据与业务不可破坏项

以下内容属于现有模型和数据边界，Muse 只能复用，不能为了视觉方便重写：

- Financial Model V1.0 公式和状态语义保持不变。
- Facts、parameters、derived results 分离。
- Planning Income 与 Actual Income 分离。
- 当前月债务事实缺失时显示待确认，不用上月值冒充本月。
- `NO_CORE_OBLIGATION` 时覆盖值为空/不可用，不显示 Infinity、NaN 或伪造月份。
- `STRUCTURAL_DEFICIT` 与 `BALANCED_NO_SURPLUS` 必须区分。
- 用户本地 `business_date` 与 instant timestamp 分离。
- 金额精度、范围和验证沿用 `docs/DATA_CONTRACT.md`。
- 不将用户个人数字写进通用公式、默认值或组件常量。
- 不用 localStorage 代替 SQLite 事实存储；奖励/偏好也不能污染财务事实。

## 7. 跨平台产品约束

- 默认沿用现有 Tauri 2 + React + Rust/SQLite 路线，先验证 iOS 编译和本地数据适配，再决定是否需要平台原生桥接。
- UI 必须是响应式布局，但“手机缩小版 macOS”不算 iOS 设计；iPhone 要有触控尺寸、数字键盘、safe area、底部 Tab 和 sheet 交互。
- macOS 要有键盘焦点、窗口缩放、sidebar、快捷入口和可读的宽屏布局。
- 财务核心和持久化契约放在共享层；平台适配只处理窗口、键盘、通知、文件选择、App Store 签名等差异。
- 发布 Bundle ID、App Group、数据库路径、签名和迁移必须先有明确方案，不得直接覆盖正式身份或正式数据库。
- App Store 发布前必须有 iOS Simulator、真实 iPhone、macOS 本地包和 TestFlight/Archive 证据；没有 Apple Developer 账号或签名信息时只能标记 `BLOCKED_EXTERNAL_ACCOUNT`。

## 8. 明确不做

- 不新增银行 API、支付宝/微信同步、云同步、多人账户、AI 投资建议。
- 不做完整投资交易、复杂预算表、24 个月预测或 0–100 健康分。
- 不把 streak、徽章或角色奖励放在财务核心之上。
- 不保留测试日期控件、WP-03 身份、测试夹具数字或“测试版”标题到正式候选。
- 不删除或重写现有迁移、Production 路径和历史验收证据。

## 9. 设计验收底线

首屏在 iPhone 390×844 和 macOS 1280×800 都必须能回答：

1. 我现在处于什么状态？
2. 我今天最值得做哪一件事？
3. 点击后会发生什么？
4. 做完以后哪个结果会更新？

如果用户不能在 3 秒内找到“记一笔”，视觉验收不通过。若要靠阅读长段解释才能理解当前状态，信息架构不通过。
