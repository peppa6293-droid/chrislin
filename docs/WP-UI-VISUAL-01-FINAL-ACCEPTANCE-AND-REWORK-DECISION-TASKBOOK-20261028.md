### 2.3 B-01～B-06 逐字冻结（Owner 已逐项回复确认，2026-10-28 统一签认后正式生效）

**B-01｜双环数据口径**
1. 固定负担 = 所选月份固定支出总额 + 必须偿还月供总额；同一笔还款不重复计入。
2. 命名统一：外环 = 固定支出占收入；内环 = 必须偿还月供占收入；中心 = 所选月份实际收入。
3. 两环分别独立计算（固定支出÷收入、必须偿还月供÷收入），不构成合计 100% 的资金分配环。
4. 结构余量只在主卡显示，不入环；公式 `(月收入−固定支出−必须偿还月供)÷月收入`。
5. 消费进度移出圆环；分类卡与圆环不要求一一对应。
6. 缺失数据不补零、不用旧月份数据、不用过期快照；收入缺失或待确认时外环同样不能计算。

**B-02｜圆环特殊状态**
1. >100%：主弧最多一整圈 + 外置超额标记；百分比与超额金额由文字承载。
2. >200%：不画多圈，文字完整显示实际比例与超额金额。
3. 外置超额标记：设计师最多 3 个候选（A/B/C，见 §4），放独立 `CANDIDATE` 目录，**Owner 选定后才进入返工与实现**；共同规则见 §4.2。深珊瑚 `#C2503C` 仅为候选色，选定前不得写进实现。
4. 整体超载 vs 单环超额分离：整体超载只由主卡负结构余量 + 负比例表达；单环 >100% 才在对应明细旁加标记并写完整数值。示例：固定支出 70% + 月供 40% → 整体超载但两环都不加标记。
5. 零收入：中心 `¥0`；两环保留中性轨道、不画弧、不显示百分比；保留可确认的固定支出与月供实际金额；沿用 D-01 零收入两句。
6. 固定负担 = 收入：显示真实比例；主卡「结构余量 ¥0 · 0%」；**中性背景 + 深色金额，不加警告图标、不加黄底条、不整圈变黄**（C-2 收敛后的最终口径）。
7. 待确认月供：外环仅在「收入已确认且 >0、固定支出数据完整」时画真实比例；内环保留中性完整轨道，不画数据弧、不加起点色点、不旋转/闪烁、不用警报红；明细「必须偿还月供　待确认」，不用 ¥0 / 0%；结构余量金额、比例、五档评级全部隐藏；不把未知月供补成 0。主标题复用「资料不齐，花点时间补一下」，结构余量位置显示弱化「—」（不附 ¥/百分比、不放大、不挖空整块），可访问名称「结构余量待确认」。
8. 禁止：除零、截断、归一化、静默改 100%、用旧快照。

**B-03｜分类进度边界**
1. 计划=0 且已付>0：逐字「计划 ¥0 · 已付 ¥Y · 超计划 ¥Y」，不显示比例。
2. 已付>计划：两行——「已付 ¥X / 计划 ¥Y」+「超计划 ¥Z · 已付/计划 N%」；百分比字段统一命名「已付/计划」。
3. 计划>0 已付=0：进度 0，标签「未付」。
4. 计划=0 已付=0：不出现 `0/0` 或 `0%`。
5. 计划缺失 ≠ 计划为 0，分别处理。
6. 实际金额不得截断、归一化或改写为计划金额；进度视觉可封顶，数值表达不封顶。
7. 已付低存在感纯文字；未付用主按钮「记一笔」；不做绿色徽章。

**B-04｜负收入**
1. 文案逐字冻结：「所选月份收入合计为负，建议核对相关流水。」
2. 保留真实负收入金额与已确认负担金额；隐藏结构余量金额、比例、五档评级。
3. 不改原始流水、不新增功能入口（不加「去核对流水」按钮、红色横幅、整卡红底）；不把负收入当零收入处理。

**B-05｜月份切换（数据一致性阻断项）**
1. 全部数据按所选月份重算（标题、五档、中心与两环比例、固定支出、月供、分类金额、已付/计划/进度、待确认债务、结构余量与超载）。
2. 请求携带月份标识；旧请求晚返回不得覆盖当前月份数据。
3. 切换期间骨架屏（保持原布局、无加载文案）；缺失只展示可确认部分并标未确认，不补 0。
4. 局部失败「这一块没读出来，点这里重试」；缓存过期/切换中断不得静默沿用旧快照。
5. 最小验证：快速连切两个月 + 人为延迟旧月份响应，证明旧响应不覆盖当前月份；截图或日志同时核对标题/金额/圆环/分类进度/待确认债务。

**B-06｜动效、图标与无障碍**
1. 动效基线（偏离须报备）：展开/收起 180ms、进度线 220ms、数字变化 160ms 淡入淡出、图标反馈 140ms；统一 `cubic-bezier(0.2, 0, 0, 1)`。首屏不播整页入场；仅用户操作或已确认数据变化触发；中断以最新已确认状态为准；`prefers-reduced-motion` 取消位移与进度生长（即时或 ≤100ms 透明度过渡）。
2. 付款提交前不播成功反馈，保存并回读成功后才反馈；数字变化与进度线同步，不逐项排队。
3. 图标：项目现用 `lucide-react`，历史规范 20px/2px/currentColor，实现中混用；**20px/2px 仅作统一候选起点，不算已签认**；先核对项目规范、缺失才提候选尺寸；图标只在层级需要时用；不引入第二套图标库/SF Symbols/新 Token。
4. 无障碍：图形对比度 ≥3:1、文字独立验收；状态不靠颜色单独表达；真实 DOM 关联；键盘焦点可见；可访问名称齐全；装饰图标避免重复朗读。
5. 对比度口径（设计师实测，不透明 sRGB）：品牌蓝绿 `#7CC9BF`/白 1.92:1、品牌黄 `#FBD83B`/白 1.40:1（均不达 3:1，不得独自承担必要数据边界或小字）；深蓝绿 `#286D65`/灰轨 `#E9EEEC` 5.17:1、深黄 `#B87700`/白 3.70:1（图形通过、文字不通过，不用于 12.5px 状态文字）、深珊瑚 `#C2503C`/白 4.66:1、深珊瑚/浅珊瑚 `#FFF0ED` 4.20:1（图形通过、文字不通过）、辅助文字 `#637372`/页面底 `#F4F6F6` 4.58:1（通过）；不用整组 opacity 表次要状态；实现阶段仍须对真实背景、边界、交互态、焦点态实测。

## 4. 超额标记候选 A/B/C 对比（供统一选择）

### 4.1 三候选对比

| 候选 | 形态 | 优点 | 缺点 / 风险 |
|---|---|---|---|
| **A｜明细旁固定警示标记**（设计师推荐） | 对应文字明细行旁放固定小型警示标记，完整数值同行可见 | 读图成本最低：标记与比例/超额金额同处；完全不干扰环读数；手机上随明细行满足 44px 触控；>200% 同规则自然延用 | 占明细行横向空间（窄屏需换行）；与环本体的图形关联较弱 |
| **B｜环起点外置标记** | 标记置于对应环起点外侧 | 图形语义强，直接指向「这条环」 | 环起点处拥挤，内环过窄；手机上易与弧重叠；标记与数值分离，需来回对照；触控区不足 44px |
| **C｜外置短端段** | 环主弧末端外接短实色端段 | 与弧连续、最紧凑 | **最易被误读为「第三条进度」或补充弧**；虽限制大小固定，仍易被读成超额量；>200% 语义最难表达 |

### 4.2 三候选共同规则（无论选哪个都生效）

1. 标记大小固定，不以长度/面积表达超额多少。
2. >100% 主弧最多一整圈；>200% 不叠圈，只用文字完整显示实际比例与超额金额。
3. 颜色限现有语义色；深珊瑚 `#C2503C` 仅为候选色（白底 4.66:1，图形通过、文字不通过）。
4. 完整数值直接可见，不藏悬浮提示。
5. 不把整体超载金额挂到单环；整体超载只由主卡负结构余量 + 负比例表达。
6. 不用红色斜纹、发光、整卡染红、多圈叠加。
