## 3. B-01～B-06 逐字冻结（Owner 已回复确认，正式签认待本补正版复核后生效）

### B-01｜双环数据口径

**已冻结规则：**

1. **固定负担定义**：所选月份固定支出总额 + 必须偿还月供总额。同一笔还款不得重复计入。
2. **命名统一**：外环 = 固定支出占收入；内环 = 必须偿还月供占收入。中心 = 所选月份实际收入。
3. **计算独立性**：外环、内环分别独立计算（固定支出 ÷ 收入、必须偿还月供 ÷ 收入），不构成合计 100% 的资金分配环。
4. **结构余量**：只在主卡显示，不入环。公式：`(月收入 − 固定支出 − 必须偿还月供) ÷ 月收入`。
5. **消费进度**：移出圆环。
6. **分类卡**：与圆环不要求一一对应。
7. **缺失数据**：不得补零、不得用旧月份数据、不得用过期快照。收入缺失或待确认时外环同样不能计算。

### B-02｜圆环特殊状态

**已冻结规则：**

1. **>100%**：主弧最多一整圈 + 外置超额标记；百分比与超额金额由文字承载。
2. **>200%**：不画多圈，用文字完整显示实际比例与超额金额。
3. **外置超额标记**：设计师最多提交 3 个候选（A 明细旁固定警示标记、B 环起点外置标记、C 外置短端段），放独立 `CANDIDATE` 目录，**由 Owner 选定后才进入返工和实现**。共同规则：标记大小固定不以长度表超额多少；颜色限现有语义色；完整数值直接可见不藏悬浮提示；不把整体超载金额挂到单环。深珊瑚 `#C2503C` 仅为候选色，未被 Owner 选定前不得写进实现。
4. **整体超载 vs 单环超额分离**：整体超载只由主卡负结构余量 + 负比例表达；单环 >100% 才在对应明细旁加外置标记并写完整数值。示例：固定支出 70% + 月供 40%，整体超载但两环都不加标记。
5. **零收入**：中心 `¥0`；两环保留中性轨道，不画弧、不显示百分比；保留可确认的固定支出与月供实际金额；沿用 D-01 零收入两句。
6. **固定负担 = 收入**：显示真实比例；主卡「结构余量 ¥0 · 0%」；中性或琉璃黄临界；不加警告图标、不加黄底条、不整圈变黄。
7. **待确认月供**：
   - 外环仅在「收入已确认且 >0、固定支出数据完整」时画真实比例；否则不画比例。
   - 内环保留中性完整轨道，不画数据弧、不加起点色点、不旋转/闪烁、不用警报红。
   - 明细显示「必须偿还月供 待确认」，不用 ¥0 或 0%。
   - 结构余量金额、比例、五档评级**全部隐藏**。
   - 不把未知月供补成 0。
8. **禁止行为**：不得除零、截断、归一化、静默改 100%、用旧快照代替当前状态。

### B-03｜分类进度边界

**已冻结规则：**

1. **计划=0 且已付>0**：逐字显示「计划 ¥0 · 已付 ¥Y · 超计划 ¥Y」，不显示比例。
2. **已付>计划**：两行显示——第一行「已付 ¥X / 计划 ¥Y」；第二行「超计划 ¥Z · 已付/计划 N%」。百分比字段统一命名「**已付/计划**」。
3. **计划>0 已付=0**：进度 0，标签「**未付**」（全项目统一使用「未付」，不再使用「待付」）。
4. **计划=0 已付=0**：不出现 `0/0` 或 `0%`。
5. **计划缺失 ≠ 计划为 0**：分别处理。
6. **硬性规则**：实际金额不得截断、归一化或改写为计划金额；进度视觉上限与实际数值表达必须同时存在。
7. **视觉表现**：已付低存在感纯文字；未付用主按钮「记一笔」；不做绿色徽章。

### B-04｜负收入

**已冻结规则：**

1. **文案逐字冻结**：「**所选月份收入合计为负，建议核对相关流水。**」（取代此前草案文案）。
2. 保留真实负收入金额与已确认负担金额。
3. 隐藏结构余量金额、比例、五档评级。
4. 不改原始流水、不新增未经批准的功能入口（不加「去核对流水」按钮、不加红色横幅/整卡红底）。
5. 不把负收入当零收入处理。

### B-05｜月份切换

**已冻结规则：**

1. 全部数据按所选月份重算（标题、五档文案、圆环中心与两环比例、固定支出、月供、分类金额、已付/计划/进度、待确认债务、结构余量和超载）。
2. 请求携带月份标识；旧请求晚返回不得覆盖当前月份数据。
3. 切换期间显示骨架屏（保持原布局，减少上下跳动，无加载文案）。
4. 数据不完整只展示可确认部分并标记未确认，不补 0。
5. 局部读取失败显示「这一块没读出来，点这里重试」。
6. 缓存过期或切换中断不得静默沿用旧快照。
7. **最小验证方式**：快速连切两个月 + 人为延迟旧月份响应返回，证明旧响应不覆盖当前月份；截图或日志同时核对标题/金额/圆环/分类进度/待确认债务。
8. 月份切换使用一个共享紧凑控件，不重复放置多套。

### B-06｜动效、图标与无障碍

**已冻结规则：**

1. **动效参数**（Owner 已接受为实施基线，实现阶段需偏离时须报备）：展开/收起 180ms、进度线 220ms、数字变化 160ms 淡入淡出（不做持续滚动）、图标反馈 140ms（不弹跳、不循环）；统一 `cubic-bezier(0.2, 0, 0, 1)`。
2. **触发约束**：首屏不播整页入场；仅用户操作或已确认数据变化触发；中断以最新已确认状态为准。
3. **reduced-motion**：`prefers-reduced-motion` 取消位移与进度生长，改即时或 ≤100ms 透明度过渡。
4. **图标**：项目现用 `lucide-react`，历史规范 20px/2px/currentColor，实现中尺寸与描边混用。**20px/2px 仅作统一候选起点，不算已签认为全局强制**。先核对现有图标规范，缺失才提候选尺寸。图标只在层级需要时使用，不强制所有状态添加图标。不引入第二套图标库、SF Symbols 或新 Token。
5. **无障碍**：图形对比度至少 3:1；文字对比度独立验收；状态不得仅靠颜色表达；真实 DOM 关联；键盘焦点可见；可访问名称齐全；装饰图标避免重复朗读。
6. **付款反馈**：提交前不播放成功反馈；确认保存并回读成功后才反馈。数字变化与进度线同步，不逐项排队。

## 6. 审美设计师独立审核整合（只读结论，已纳入执行方案）

本节整合审美设计师对 Apple App 原生感、视觉层级、双环表达、移动端和交互可用性的复核；不构成改稿或开发授权。

### 6.1 必须纳入验收的视觉/交互边界

1. **整体超载与单环超载必须分层表达。** 固定支出占收入 70%、必须偿还月供占收入 40% 时，即使两个单环均未满，整体固定负担仍为 110%；此时主卡必须表达负结构余量、负比例及已确认超载，不能等单环满圈才提示，也不得把整体超载金额归给某一个圆环。
2. **双环不是"越满越好"的完成环。** 双环只表达各自占所选月份收入的比例；单环超 100% 的真实比例和超额金额由文字承载，不能用多圈制造进度感。
3. **超额视觉候选不得直接定稿。** 推荐优先评估"主弧最多一圈 + 对应明细旁固定的小型外置警示标记"；标记大小不表达超额数值，不使用红色斜纹、发光、整卡染红或叠加多圈。也可在限定范围内由设计师提交不超过 3 个候选，Owner 另行确认。
4. **圆环操作入口必须可理解、可键盘使用。** 两个文字明细行应是可靠点击/键盘入口，圆环点击只能作为辅助；选中后突出对应环但保留另一环边界，不依赖悬浮气泡，不新增页面；再点取消选择的行为须在实现规格中明确。月份使用一个共享紧凑控件，不重复放置多套月份切换。
5. **待确认债务不能制造错误进度感。** 外环可继续显示已确认固定支出，内环明确显示"待确认"，不画旧弧、不留看似真实的旧数据空洞；结构余量金额、比例和五档评级按 B-02 的 Owner 决策执行。
6. **负收入是异常状态而非警报改账。** 保留真实负收入金额，不画正常进度弧、不显示占比或五档评级；视觉应克制，不新增"去核对流水"入口，除非产品已有可复用入口。

### 6.2 Apple 原生感与信息层级候选

- 推荐信息顺序为"现在是什么情况 → 为什么 → 我接下来能做什么"；主卡与双环形成同一概览整体，手机上下排列，宽屏左右排列；不得借此删除已确认信息或擅自改变正式业务结构。
- 品牌个性集中在已确认梗文案、少量品牌色和关键反馈；避免厚投影、悬浮抬升、弹跳、过多渐变、彩色底托和卡片套卡片。
- 金额使用统一等宽数字与对齐方式，不增加字号档位；动态字体放大时允许换行和增高，不为满足固定字号而截断内容。
- 付款提交前不播放成功反馈；必须在确认保存并回读成功后反馈。数字变化与进度线同步，不逐项排队播放；骨架屏保持原布局，减少上下跳动。
- 现有项目 Lucide 20px/2px 规范可作为候选起点，但不等于本轮最终签认；不得新增 SF Symbols、第二套图标库、依赖或 Token。
- **Web/Tauri 原生风格设计 ≠ 已采用原生系统控件**，不得凭外观截图宣称原生体验。

### 6.3 移动端和短视口阻断项

- 真实 390×844 首屏须压缩无效留白和重复月份/层级，使第一个有效功能模块不再被推迟到约 1003px；不得靠缩字号、隐藏已确认数据或删除模块解决。
- 390×520、软键盘、日期弹层和动态字体必须有独立证据；金额字段、当前焦点和"确认付款"在键盘出现时必须可达。长截图不能替代真机或等效交互证据。
- 760、980/1000、1440 仍按本任务书既定容器和单列/双列规则验收；760–880 仅在备注宽度不足 240px 时降级三行，宽屏不得回退。

## 9. 验收标准与证据

### 9.1 业务/视觉

- D-01 七句及零收入文案逐字一致；
- 每个圆环有明确分子、分母、月份、标签；
- 零收入不出现百分比；临界、超载、待确认债务可复现；
- 超载真实比例、负余量、超额金额不截断或归一化；
- 分类 0%、超付、计划为 0 均有明确显示；
- 月份切换不串数据、不使用旧快照。

### 9.2 页面/响应式

- 正式容器以 `.finance-page` 实际 980px、`.detail-page` `max-width:800px` 为准；1120px 仅作展示稿；
- 验收宽度为 760、980/1000、1440；760–880 备注不足 240px 时降级三行，1000 单列，1440 双列；
- 不横向溢出，不让底部导航永久遮挡关键操作；短视口、软键盘、日期弹层、动态字体有独立证据；
- 字号封顶：34 主数字、22 行金额、16 卡题、12.5 辅助说明；
- 颜色不作为唯一状态表达，图形元素满足 3:1。

### 9.3 文案/资产

- 现网原文逐字保留，复用文案注明来源，新增文案只用 `P-`/`H-`/`E-` 槽位；
- 统一使用「**未付**」（Owner 决策 §5-3）；不得出现设计注释、示例数据、演示或占位；
- 旧稿、候选稿和审核标记不得被误当正式基线；
- 证据放在 `evidence/wp-ui-visual-01/`，每个状态提供截图、源文件、复现命令和断言。
