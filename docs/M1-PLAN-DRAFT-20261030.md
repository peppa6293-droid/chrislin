## 3. smoke 何时切到正式包名，影响什么

### 3.1 已验证的现状

- **已验证：** 当前安装身份是 `com.personalfinance.console.smoke`；基础 tauri.conf.json 写的是 `com.personalfinance.console`。这两个配置中的显示名称均为“小钱家”；显示名称和 Bundle ID 是两回事。
- **已验证：** 当前开发 Team 为 `SSRKA7A4TN`；已核验描述文件的 application-identifier 为 `SSRKA7A4TN.com.personalfinance.console.smoke`，不能把它原封不动用于另一个显式 Bundle ID。
- **已验证：** 现有生产标识启动检查仍强制 macOS 的 `/Applications/Personal Finance Console.app/Contents/MacOS/personal-finance-console` 路径。原样切标识并不能形成可用的 iOS 正式版，不能通过删除安全检查来绕过。
- **待验证／待确认：** 最终 iOS 正式 Bundle ID 是否采用 `com.personalfinance.console`、对应 App ID/发布记录/能力配置是否可用；当前基础配置不是 iOS 发布审批记录。

### 3.2 建议切换时点：不在本轮，也不因 M0 通过就自动切

| 顺序 | 前置条件 | 状态 |
|---|---|---|
| 1 | Owner 完成 M0 人工确认 | 待验证：当前明确未收尾 |
| 2 | 确认 M1 最小页面/数据范围与 iOS 首次数据来源 | 待验证／待确认 |
| 3 | 验证 iOS 专用启动、全新数据库及升级/恢复路径，证明不访问或混用 smoke/Mac 正式数据 | 待验证 |
| 4 | 冻结正式 Bundle ID，核验对应 App ID、能力、描述文件、Team 与证书；核对手机是否已有同正式 ID 的 App | 待验证／待确认 |
| 5 | 获得明确的正式构建/安装授权后才切换，验证首次安装、重启、升级、数据回读及必要通知权限 | 待验证／待确认 |

### 3.3 切换后的影响

| 项目 | 可以确认的结论 | 状态 |
|---|---|---|
| 签名与描述文件 | 新 Bundle ID 必须匹配相应 App ID 和描述文件；不能保证现有 smoke profile 直接可用。证书不必因名称变化就断言要重建，但现有证书/Team 能否继续用于正式包必须核验 | 已验证：Apple 身份/签名规则及当前 profile。待验证：本项目正式签名组合 |
| 已装 smoke App | 与不同正式 Bundle ID 属于不同应用身份，正常情况下新包不会作为 smoke 的原位升级；本项目并存安装、图标区分和权限需要实机核对 | 已验证：平台身份规则。待验证：本项目并存实测；本轮不卸载 smoke |
| 已有正式 ID App | 如果手机已有相同正式 Bundle ID，安装可能是对它的升级/覆盖，不能保证“所有已装 App 都不受影响” | 待验证：当前设备上是否存在、版本与数据；正式安装前必须核对 |
| 数据 | iOS 默认给每个 App 独立数据容器；换 ID 不会自动搬迁旧测试账本。任何 App Group/共享目录、备份导入或显式迁移仍需独立设计与验证 | 已验证：Apple 沙盒规则。待验证：项目正式库路径和任何迁移行为 |
| 通知和显示名 | 不能把 smoke 的通知许可当成正式身份已获许可；相同显示名也不代表同一个 App | 待验证：正式包通知许可、排程/取消/点击及用户辨识；显示名与 ID 不同这一点已验证 |
| 后续发布 | 首次上传 App Store Connect 前应确定 Bundle ID；上传后不能把同一应用记录任意改成另一个 Bundle ID | 已验证：Apple 官方文档；是否进入 TestFlight/App Store 不属于本次授权 |
