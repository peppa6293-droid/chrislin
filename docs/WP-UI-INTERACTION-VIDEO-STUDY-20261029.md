## 2. 设计结论

先把“操作是否收到、是否保存成功、数据为什么变了”做清楚，再考虑花哨转场。

小钱家是金额工具，准确、稳定、好撤回比动画新奇重要。六种效果不全上，按下面的取舍做。所有时长来自已生效 D-08/B-06，**不是从视频量出来的参数**。

| 原视频项（名称已核实） | 小钱家适配（设计建议） | 取舍与优先级 |
|---|---|---|
| 完成反馈按钮 | 记账/记录付款：按下有反馈；提交中禁止重复；确认保存及回读成功才显示完成；失败留住输入和焦点 | 第一优先；沿用已有反馈，不叠第二套成功弹层 |
| 勾选联动 | 借鉴“状态联动”，不新加付款勾选功能；已有保存完成后，条目、相关合计及进度同步切到同一确认结果 | 第一优先；勾选不等于已付款，严禁一勾自动写账 |
| 叠卡展开 | 借鉴原位展开的连续性，放在 P3 的付款日期/备注详情；总额和当前输入保持可见，收回后焦点仍在原触发处 | 第二优先；不用卡片叠压隐藏真实账目，不将首页分类卡改成可点 |
| 吸附卡加画线 | 此名称的具体实现待视频补证；目前只保留现有条形进度 220ms 的增长反馈，不推定原作者手势或图表行为 | 原效果暂缓；不增加首页横滑卡，不修改圆环几何 |
| 惯性滚轮 | 暂不引入；日期沿用现有日期控件，月份保留明确按钮；金额坚持精确键入 | 不采用金额滚轮；如以后考虑月份滚轮，先验证键盘/读屏和防误选 |
| 圆形扩散转场 | 高频记账/切月不采用；大范围遮罩容易盖住金额并制造等待 | 暂不采用；不能因参考视频自动放行全站转场 |

## 4. 三项优先优化的状态与验收要求

### A. 记完一笔，反馈就在操作附近

- 空闲：原按钮、原文案；不增加新字符串或 aria 名称。
- 按下：即时可感知，不等网络；只用现有轻量反馈，禁止按钮和父容器重复弹跳。
- 提交中：保留金额/日期/备注；阻止重复提交；既有状态说明可复用，缺文案先编号留槽，不写新正式文案。
- 确认成功：以已保存并回读的结果为准，图标反馈 140ms；反馈与金额更新同步，不人为延迟成功，不再套第二个庆祝层。
- 未确认/失败：不播完成、不清空输入、不把错误当成功；保留可重试入口；是否可安全重试由功能审核检查，设计稿不假定幂等。
- 离开/快速再操作：取消过期动画，不回放上次成功；键盘焦点与操作无需等动画结束。
- 验收：慢响应、失败、未确认、双击、键盘提交与快速再记一笔，各自结果正确，无重复写入、无虚假成功。

### B. 改一处，相关信息一起更新

- 不增加“打勾即还款”或批量支付功能。沿用现有明确提交动作。
- 展示更新须来自同一次已确认结果、同一月份；条目、合计、进度不允许新旧结果混搭。
- 数字采用 160ms 淡入淡出，不滚动计数；进度 220ms；两者同步开始，不排队播放。
- 缺失/待确认/零收入等状态保持真实；不为动画补零、不硬凑 100%、不改变分母。
- 月份切换只接受最新请求对应月份的结果。该竞态修复仍归 P4 技术任务，不在本稿中宣称已解决。
- 验收：延迟旧请求后连续切两个月；旧结果不能覆盖新月份；金额、进度和所选月份始终一致。

### C. 付款详情从原位置展开

- 放入已有 P3 范围，不新增另一种付款面板，不将首页不可点分类卡改成可点。
- 日期/备注展开收起 180ms，统一缓动；金额与提交按钮位置尽量稳定。
- 折叠时不吞掉已填内容；收起后的焦点回到可见触发处，不能遗留在隐藏内容里。
- 390×520 + 真实软键盘：当前输入和必要操作可滚动到，不锁死页面；日期弹层不可被层级或裁切遮挡。
- 验收：鼠标、触控、Tab/Enter/Space、反复展开收起、200% 字体、读屏、真实键盘；真机未测只能 PARTIAL，不能以桌面截图替代。

## 5. 统一约束

- 使用正式 D-08 参数：展开/收起 180ms，条形进度 220ms，数字淡入淡出 160ms，图标 140ms；`cubic-bezier(0.2, 0, 0, 1)`。首屏不播整页入场，不循环、不弹跳。
- `prefers-reduced-motion`：取消位移与进度生长，使用即时或 ≤100ms 淡变；状态、焦点、业务结果不减少。
- 不增加依赖、第二套 Token、图标库；复用现有 React/CSS/WAAPI。具体实现与文件白名单由审核方案确定，设计稿不擅自放行。
- 不改业务模型/持久化/数据库、生产门闸、圆环口径与几何；R1 与 OPEN-F6 原待办不被本稿覆盖。
- 文案逐字复用已批准内容。新增可见/aria 文案先留编号槽位，不能擅自用“保存中/保存成功”等示例成为正式新文案。
- 目标是减少不确定感，不增加动画等待；任何动画不能挡住金额、改变账目或抢走输入焦点。
