## 1. 红线（违反即停手报告）

1. **双账本同步契约（D-01，`docs/EXEC-D01-LEDGER-SYNC-INSTRUCTIONS.md`）**：V2 支出写入必须同事务镜像写入 V1 `expense_records`。本任务书扩展三条，扩展后契约同样必须成立：
   - **删除**（WP3 第 9 项）：删 V2 `expenses` 与 V1 `expense_records` 同事务双删，两本账可对账；
   - **还款**（WP2 第 7 项）：还款同步 V2/V1 两本账，同事务；
   - **编辑**（WP3 第 9 项）：改 V2 支出同事务同步 V1 镜像行。
   每条扩展实现后须补对账断言（记/改/删/还后两本账一致），回执中给出验证结果。
2. **生产库完整性门闸**：数据只走应用界面与应用层服务写入，**禁止直插 SQL 改库、禁止改库凑数**；启动完整性头校验不得绕过。
3. **改代码→重建→安装必撞包指纹门闸**（`PRODUCTION_TERMINAL_CANDIDATE_BINDING_MISMATCH`）。发布须走 R13B 热修授权字段级重绑定流程（§6，引用 `docs/EXEC-R13B-HOTFIX-RELEASE-REBIND.md` §1–§3），**户主签发热修授权后方可重绑定**。
4. **测试门**：`npm test` 全量不红、`npm run lint`、typecheck 全绿；回归基线与现有证据对齐（R13B 后全量 444 passed / 0 failed / 80 skipped 为参考基线，以执行时实测为准）。
5. **验收锚点分「当月/全量」两口径**登记（沿 R13B 结论）。
6. 遇契约两难（例如必须改 D-01 映射、必须动 schema）：**停下报告，回批户主**，不得自行抉择。

## 2. WP1 · P0 日常体验（第 1–5 项）

### 2.1 首页拆卡（第 1 项）
- 位置：`src/ui/V2HomeSurface.tsx` 卡片区块（约 :455–495）。
- 拆为两张卡：
  - **结构卡（长期）**：收入 − 固定支出 − 月供 = 结构余量（即 `baseSurplus` 口径），配一句大白话（「这是长期格局，改收入/固定支出/债务才会变，不用每月盯」）。进度条基准改为「结构余量占收入比例」，文案不再用「还可以安排」这种可行动语气。
  - **本月消费卡（短期）**：已花 vs 目标（`currentMonthSpending` / `desiredMonthlyDiscretionarySpending`），多邻国式动画进度条，超支变色+提示。
- 提醒改「可行动才出现」：本月超支、还款日临近、逾期；**结构性长期缺口不再每月重复提示**。
- `statusCopy` 三态文案随两卡拆分重写，说人话。

### 2.2 记账反馈层（第 2 项）
- 位置：`V2HomeSurface.tsx` `saveExpense()`（约 :170–190，现为关弹窗+一行文字）。
- 要求：记完一笔 = 庆祝动画（弹跳/粒子/进度条增长）+ 本月进度即时更新；记完一天 = 完成感（可带连续天数）；记完一月 = 月度小结庆祝页（PPT 式图文）。
- 视觉：多邻国圆润风。可参考 `src/ui/DuoGuide.tsx`（连击/奖励状态机）、`src/ui/SaveFeedback.tsx`（粒子庆祝）的交互逻辑；**像素视觉不得照搬**。
- 尊重系统减弱动效设置（现有 `reducedMotion` 惯例延续）。

### 2.3 日期控件（第 3 项）
- 现状：`datetime-local`（约 :1045–1145，标签「日期和时间」）。
- 改为：日历式日期选择器（大尺寸、可点选，不是原生小输入框），**只要日期不要时间**。
- 存储安全已核实：`src/application/v2-expense-service.ts` 只收 `YYYY-MM-DD` 业务日期（`assertCalendarDate`），`occurredAt` 恒为 `T00:00:00.000Z`，砍时间无损。
- 若引入第三方日期组件，先报依赖变更；优先无依赖自绘日历。

### 2.4 路由 bug：「建立余地」（第 4 项）
- 实锤：`V2HomeSurface.tsx` 进度项「稳住现金」与「建立余地」**都路由 `SAFETY_DETAIL`**（约 :733、:755）。
- 修：「建立余地」建独立页面（储蓄/余地目标的图文进度页，一屏一个问题），路由常量新命名；**全量清查所有导航项路由是否有复制粘贴错**，回执列出清查结果。

### 2.5 金额格式统一（第 5 项）
- 全 App 统一「¥ + 千分位 + 两位小数」。重点：`src/ui/v2-dashboard.tsx` `formatAmount`（现裸数字如 9309.32）及各详情页。抽公共格式化函数，不许各处自写。

## 3. WP2 · P1 账本分层（第 6–8 项）

### 3.1 固定支出独立页面（第 6 项，户主口径已定）
- 从 `src/ui/FinancialMaintenanceDialog.tsx`（必要支出维护区块）抽出独立页面，入口放首页结构卡直达；综合维护对话框保留为高级入口。
- **两个能力缺一不可**：
  1. **维护**：增删改必要支出项（HOUSING/BASIC_FOOD/TRANSPORT/UTILITIES_COMMUNICATIONS/INSURANCE/FAMILY_FIXED_RESPONSIBILITY/OTHER_ESSENTIAL）；
  2. **记一笔实际支付**（如「这个月房租已转 ¥xxxx」）留支付记录。
- **口径（户主 2026-10-23 确认）**：维护与支付记录只进固定支出账，**不进弹性消费账**，模型不重复计入；首页结构卡「固定支出」以本账为准。
- 支付记录存储：优先复用现有必要支出/月度事实结构（`src/application/financial-maintenance-service.ts`）；**若确需新表/新列属 schema 变更，停下出迁移方案回批户主**（§1.6），不得自行迁库。

### 3.2 债务「记一笔还款」（第 7 项，红线）
- 债务页（`src/ui/HomeScreen.tsx` `DebtDetail`）增「记一笔还款」：选债务、填实还金额、日期 → **余额自动扣减 + 还款流水可查**。
- 页面数字主次反转：**本月要还（大字）**，总负债余额（小字参考）；「计划计入」与「实还」分开标注（现状文案「不代表已经还款」的误导一并消除）。
- **契约**：还款同事务同步 V2/V1 两本账（V1 债务事实 `current_balance` 更新 + 流水留痕），补对账断言。流水存储若需 schema 变更，同 §3.1 停手回批规则。
- 既有红线提醒：`saveDebt()` 只存当月债务事实，不是还款记录——两者并存不互斥，界面文案要区分。

### 3.3 分类显示修复（第 8 项，注意契约）
- **根因 A（镜像压平）**：D-01 契约明文规定镜像 `category` 固定写 `'OTHER_VARIABLE'`（V2 分类是自由创建的名称/图标，与 V1 十二值枚举无对应，契约禁止猜测映射）。**推荐修法：显示层改读 V2 分类名**（`expenses` 表的分类），V1 镜像保持不动——V1 模型只按 `kind='VARIABLE'` 汇总，`category` 仅影响展示，此修法不动契约、不动模型。执行者若认为必须改 D-01 映射，按 §1.6 停手回批。
- **根因 B（导入整批一个分类）**：见 §3.4。
- 顺带修首页读压平数据的问题（产品服务 `product-service.ts` 的 `currentMonthSpending` 链路），使首页分类展示真实分类。

### 3.4 已导入 824 笔批量重归类（第 8 项）
- 按商户名/摘要规则生成批量建议分类，**用户一次确认**（可批量改），之后走正常写路径更新分类。
- **禁止**改金额、日期、账目内容；禁止直插 SQL；重归类经应用层服务写入并保持双账本一致（V1 镜像 `category` 依 §3.3 结论处理）。
- 锚点：重归类前后总额/笔数不变（参考全量导入总额 100,450.11、笔数 825/826 口径，以执行时实测为准，当月/全量分开登记）。

## 4. WP3 · P2 数据可信（第 9–12 项）

### 4.1 删除/编辑流水（第 9 项，红线）
- 流水列表每条支持删除、编辑；删除前二次确认 + 短时撤回窗口。
- **契约**：删除/编辑同事务双账本同步（§1.1），补对账断言；删除留审计痕迹（谁/何时/删了什么），防误删后无据可查。

### 4.2 数据导出（第 10 项）
- 一键导出到本地文件：**JSON 全量备份**（三本账全部数据+设置）+ **CSV 流水表**；文件名含日期。
- 导出走本地文件对话框/下载，数据不出机器；隐私页同步补说明（数据存在哪、怎么迁移、导出格式）。

### 4.3 导入智能化（第 11 项）
- 现状：仅支付宝/微信 CSV、整批一个默认分类+账户、逐条核对（`src/ui/v2-import.tsx`、`src/model/v2-import.ts`）。
- 改为：**丢账单 → 自动分析归类 → 用户一键确认**。
  - 格式识别逐步覆盖常见银行/平台 CSV（支付宝/微信保持兼容）；
  - 自动归类：本地规则库（商户名/摘要 → 分类/账户）为主，可选接入本地/开源小模型，**数据不出机器**；
  - 每笔给建议分类+置信度，**低置信度才标出**让用户看，高置信度一键全过；可批量改。
- 模型选型（纯规则库 vs 本地小模型）由执行者评估后在回执说明，不在本任务书锁死；**不得调用云端 API 处理用户账单**。

### 4.4 收支账本去重（第 12 项）
- `src/ui/HomeScreen.tsx:303` 折叠块「收支账本」= 重复的财务概览（`v2-dashboard.tsx`）。有价值内容（趋势、资产债务）并入主页信息架构，纯重复删除或收进二级页；资产/债务必需名称占位不丢。
