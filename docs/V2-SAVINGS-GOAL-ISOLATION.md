# V2 储蓄目标隔离说明（EXEC-L-05）

## 范围

本文件对应 `EXEC-L-05`，仅覆盖隔离 V2、synthetic fixtures、Decimal 计算和 mock 场景。它不是 Production 功能、不是正式发布说明，也不代表项目验收完成。

## 核心口径

- **目标金额**：用户设定的储蓄总数。
- **当前已存**：已经为该目标存入的金额。
- **缺口**：`目标金额 - 当前已存`，不能为负数。
- **月均保留**：按剩余月份将缺口均摊，使用 Decimal 避免浮点误差。
- **状态**：`ON_TRACK`（正常推进）、`COMPLETED`（已存够）、`SHORTFALL`（不足一个月且仍有缺口）、`OVERDUE`（目标日期已过但还没存够）。
- 所有中文说明面向普通用户，不使用未定义的金融术语。

## 与 L-04 的衔接边界

L-05 通过只读调用 L-04 的 `calculateBillStatus(bill, { asOf, availableCash: "0.00" })` 获取每张信用卡账单的 `remainingAmount`。将所有待还金额求和后，从可用现金中扣除，得到真正可以安全用于储蓄的金额。

```text
可存金额 = max(0, 可用现金 - Σ(各账单 remainingAmount))
```

关键约束：
- L-05 **不修改** L-04 的任何文件或逻辑；
- L-05 仅读取 `calculateBillStatus` 返回的 `BillStatus.remainingAmount`；
- 如果待还账单总额超过可用现金，可存金额归零而不是变成负数；
- 到期账单所需的还款资金不会被误判为可存资金。

## Synthetic 验证覆盖

专项测试覆盖：
- 正常创建与金额标准化；
- 正常计划计算（8个月、gap、月均）；
- 已完成目标；
- 逾期目标（日期已过仍有缺口）；
- 跨年月份计算；
- 非法金额、非法日期、空名称、已存超过目标；
- L-04 衔接：有账单时扣除待还再算可存金额；
- 无账单时可存金额等于可用现金；
- 现金不足以覆盖账单时的安全处理。
