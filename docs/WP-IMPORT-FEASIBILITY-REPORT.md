# 小钱家 V2 — I-01 官方 API/OAuth 可行性正式评估报告

**任务：** EXEC-I-01（XQJ-V2-REVIEW-ASSIGN-001）  
**评估人：** 小钱家审核员（基于公开资料核验，非初步预判）  
**日期：** 2026-10-16  
**结论状态：** `VERIFIED_INFEASIBLE`（个人消费账单 API 直连不可行） → 建议转为 `OFFICIAL_FILE_IMPORT_ONLY`

---

## 一、评估范围与方法

本报告仅核验以下两个平台的**官方公开文档与开发者政策**，不涉及任何逆向工程、模拟登录或非官方接口探测：

1. **支付宝开放平台**（open.alipay.com）
2. **微信支付 / 微信开放平台**（pay.weixin.qq.com / open.weixin.qq.com）

核验维度：个人开发者是否可通过 OAuth 或官方 API 拉取自身历史消费明细。

---

## 二、支付宝官方能力核验

### 2.1 开放平台定位
- 支付宝开放平台面向**商户（B端）**和**服务商（ISV）**。
- 核心 API 类别：支付创建、退款、订单查询、对账文件下载等。
- 所有交易类 API 均要求**商户身份**（需营业执照）并通过应用审核。

### 2.2 个人用户数据读取
- **不存在**面向个人用户的"我的账单"读取 API。
- 个人用户无法通过 OAuth 授权第三方应用获取自己的消费流水。
- 支付宝 App 内提供"账单导出"功能，支持导出 CSV 或 PDF（路径：我的 → 账单 → 右上角 ··· → 开具交易流水证明 / 账单导出）。

### 2.3 隐私与安全
- 蚂蚁集团《隐私权政策》明确：交易数据属于敏感个人信息，不向未经授权的第三方提供。
- 即使商户调用 `alipay.trade.query`，也只能查询**该商户自身**的交易，不能跨商户拉取用户全量消费。

### 2.4 结论
| 项目 | 结果 |
|---|---|
| 个人开发者能否申请消费账单 API | ❌ 不能 |
| OAuth 授权第三方读取个人流水 | ❌ 不支持 |
| 官方允许的替代路径 | ✅ 用户手动导出 CSV/PDF |
| 风险等级 | 低（CSV 为本地文件，不经网络传输） |

---

## 三、微信支付官方能力核验

### 3.1 微信支付商户平台
- 微信支付 API（v3）面向**已签约商户**。
- 核心能力：下单、退款、对账单下载、分账等。
- 所有接口需商户证书签名 + APIv3 密钥。

### 3.2 微信开放平台
- 微信 OAuth（`wx.login` / `scope=snsapi_userinfo`）仅提供用户基本身份信息。
- **不提供**交易记录、账单明细的读取权限。
- 微信小程序内可调用 `wx.requestPayment` 发起支付，但无法反向拉取历史支付列表。

### 3.3 个人账单导出
- 微信 App 提供"钱包 → 账单 → 常见问题 → 下载账单"功能，支持导出 CSV（用于个人对账）。
- 导出的 CSV 包含：交易时间、交易类型、商品名称、金额、支付方式、交易单号等字段。

### 3.4 结论
| 项目 | 结果 |
|---|---|
| 个人开发者能否申请消费账单 API | ❌ 不能 |
| OAuth 授权第三方读取个人流水 | ❌ 不支持 |
| 官方允许的替代路径 | ✅ 用户手动导出 CSV |
| 风险等级 | 低（CSV 为本地文件） |

## 四、综合评估结论

### 4.1 正式结论

```text
结论状态：VERIFIED_INFEASIBLE（API 直连不可行）
建议转向：OFFICIAL_FILE_IMPORT_ONLY（官方账单文件导入）
```

**理由：**
1. 支付宝和微信支付均不向个人开发者开放消费账单读取 API。
2. OAuth 机制在这两个平台上均不支持"授权第三方读取本人交易流水"的场景。
3. 两个平台均提供了官方的 CSV/PDF 账单导出功能，这是唯一合规的数据获取路径。

### 4.2 可行替代方案：官方账单文件导入

基于上述结论，建议将 WP-IMPORT 方向调整为**官方账单文件导入**，流程如下：

1. 用户在支付宝/微信 App 中手动导出 CSV 账单；
2. 用户在小钱家中选择"导入账单"，选取本地 CSV 文件；
3. 系统解析 CSV（识别平台格式差异）；
4. 展示待导入预览（含分类建议）；
5. 自动检测重复交易（基于交易单号 + 金额 + 日期哈希）；
6. 允许用户修改分类、账户、备注、日期；
7. 用户点击"确认导入"；
8. 写入本地 SQLite 账本；
9. 回读验证写入结果；
10. 校验金额、日期一致性；
11. 反馈导入成功/失败/部分成功。

### 4.3 隐私与安全影响

| 维度 | 评估 |
|---|---|
| 数据传输 | 纯本地操作，CSV 不上传任何服务器 |
| 密码存储 | 不需要存储支付宝/微信密码 |
| 授权撤销 | 用户随时可删除导入的记录 |
| 审计追踪 | 每次导入生成 audit log（时间、文件名、导入条数、跳过条数） |
| 合规性 | 符合两个平台的用户协议（用户使用自己导出的数据） |

### 4.4 是否建议继续投入 API 直连方向

**不建议。** 在监管政策和平台规则未发生根本变化前，个人消费账单 API 直连在中国大陆不具备可行性。建议将研发资源集中在 CSV 导入体验优化上。
