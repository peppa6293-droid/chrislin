## 3. Owner 必须补正的 B-01～B-06

### B-01｜双环数据口径（草案方向：C）

草案提出：两个独立同心环，共用所选月份月收入为分母；外环为固定支出总额÷月收入，内环为必须偿还月供总额÷月收入；中心始终为所选月份月收入，缺失时显示待确认；两环是独立比例，不构成合计 100% 的资金分配环；消费进度移出圆环；分类卡不与圆环分段一一对应。

Owner 必须确认：

1. “固定负担”统一定义为「所选月份固定支出总额 + 必须偿还月供总额」；“债务圆环”正式改称「必须偿还月供圆环」；
2. 外环、内环、中心金额、月份和标签的最终文字；
3. 分类卡与圆环不一一对应是否生效；
4. 结构余量是否只在主卡显示，不进入圆环分段；
5. 固定支出与月供的分子、分母、缺失状态均可独立验收。

### B-02｜圆环特殊状态

草案已给出：

- **零收入：** 中心 `¥0`；两环保留中性轨道，不画进度弧；展示可确认的固定支出与月供实际金额；不显示占比和结构余量比例；
- **负担=收入：** 显示真实比例；主卡「结构余量 ¥0 · 0%」；使用琉璃黄/中性临界，不使用超载红；
- **超载：** 显示真实负余量和负比例；超额使用实色端段，不默认红色斜纹；单项 >100% 不得只画满圈；>200% 必须文字明示完整数值；
- **待确认债务：** 固定支出环仍展示；月供环显示「待确认」；不画旧快照弧，不显示月供比例和五档评级，不把未知月供补成 0。

Owner 必须补正：

1. >100% 的最终画法：主弧最多一整圈，超额用独立端段或外置标记；>200% 不得画两圈以上；百分比与超额金额由文字承载；
2. 超额端段的颜色、端点样式；若授权设计师提候选，须明确授权范围；
3. 待确认债务时结构余量**金额**是否也隐藏（建议与比例、评级一并隐藏）；
4. 明确不得除零、截断、归一化、静默改为 100% 或用旧快照代替当前状态。

### B-03｜分类进度边界

草案已给出：

- 计划>0、已付=0：进度 0，标签「未付」；
- 已付>计划：轨道上限 100%，另标超额，同时保留实际已付、计划、已付占计划和超额金额；
- 计划=0、已付>0：显示「计划 ¥0 · 已付 ¥X · 无法计算比例」，不计算普通百分比。

Owner 必须逐字确认或修改候选文案：

- 「计划 ¥0 · 已付 ¥X · 无法计算比例」；
- 「超计划 ¥200（120%）」；
- 百分比字段称「已付占计划」，不称「实际比例」。

硬性规则：已付不得静默截断、归一化或改写为计划金额；进度视觉上限与实际数值表达必须同时存在。

### B-04｜负收入

草案选择独立异常状态（B），候选文案为：「收入：本月是负数，先核对流水。」

Owner 必须确认：

1. 上述文案是否逐字冻结；
2. 保留实际负收入金额；
3. 不画正常进度弧、不显示占比和五档评级；
4. 继续展示可确认的固定负担金额；
5. 不把负收入当零收入、不静默修改流水；
6. 不得擅自新增“进入流水核对入口”，除非现有产品已有可复用入口。

### B-05｜月份切换

切换月份后，标题、五档文案、圆环中心与两环比例、固定支出、月供、分类金额、已付/计划/进度、待确认债务、结构余量和超载必须全部按所选月份重算。

必须补齐以下验收规则：

- 月份请求必须携带所选月份标识；旧请求晚返回不得覆盖当前月份；
- 切换期间显示骨架屏；
- 数据不完整只展示可确认部分并标记未确认，不补 0；
- 局部读取失败显示「这一块没读出来，点这里重试」；
- 缓存过期或切换中断不得沿用旧快照。

### B-06｜动效、图标与无障碍

草案候选规格：

- 展开/收起 180ms；进度线生长 220ms；数字变化 160ms 淡入淡出，不做持续滚动；图标反馈 140ms，不弹跳、不循环；缓动统一 `cubic-bezier(0.2, 0, 0, 1)`；
- 首屏不播放整页入场，仅用户操作或已确认数据变化触发；中断以最新已确认状态为准；
- `prefers-reduced-motion` 关闭位移与进度生长，改即时或 ≤100ms 透明度过渡；
- 沿用现有图标体系，不新增依赖、Token 或图标库；无明确现值时，列表图标 20px、主功能 24px、描边 1.8px 仅为候选基线；
- 状态不得仅靠颜色；图形对比度至少 3:1；折叠控件 `aria-controls` 必须指向真实共同字段容器；`aria-expanded` 与实际一致；键盘可达且焦点可见；纯图标按钮有可访问名称；装饰图标避免重复朗读。

Owner 必须确认：

1. 上述时长、触发、中断和 reduced-motion 规则；
2. 候选尺寸/描边是否冻结，或授权设计师在限定返工中提出候选；
3. 图标仅在视觉层级需要时使用，不强制所有状态添加图标；
4. 图形对比度与文字对比度分别按各自标准验收；
5. `aria-controls` 真实节点、焦点和非颜色状态证据为必交证据。

## 5. 审美设计师独立审核整合（只读结论）

本节整合审美设计师对 Apple App 原生感、视觉层级、双环表达、移动端和交互可用性的复核；不构成改稿或开发授权。

### 5.1 必须纳入验收的视觉/交互边界

1. **整体超载与单环超载必须分层表达。** 固定支出占收入 70%、必须偿还月供占收入 40% 时，即使两个单环均未满，整体固定负担仍为 110%；此时主卡必须表达负结构余量、负比例及已确认超载，不能等单环满圈才提示，也不得把整体超载金额归给某一个圆环。
2. **双环不是“越满越好”的完成环。** 双环只表达各自占所选月份收入的比例；单环超 100% 的真实比例和超额金额由文字承载，不能用多圈制造进度感。
3. **超额视觉候选不得直接定稿。** 推荐优先评估“主弧最多一圈 + 对应明细旁固定的小型外置警示标记”；标记大小不表达超额数值，不使用红色斜纹、发光、整卡染红或叠加多圈。也可在限定范围内由设计师提交不超过 3 个候选，Owner 另行确认。
4. **圆环操作入口必须可理解、可键盘使用。** 两个文字明细行应是可靠点击/键盘入口，圆环点击只能作为辅助；选中后突出对应环但保留另一环边界，不依赖悬浮气泡，不新增页面；再点取消选择的行为须在实现规格中明确。月份使用一个共享紧凑控件，不重复放置多套月份切换。
5. **待确认债务不能制造错误进度感。** 外环可继续显示已确认固定支出，内环明确显示“待确认”，不画旧弧、不留看似真实的旧数据空洞；结构余量金额、比例和五档评级按 B-02 的 Owner 决策执行。
6. **负收入是异常状态而非警报改账。** 保留真实负收入金额，不画正常进度弧、不显示占比或五档评级；视觉应克制，不新增“去核对流水”入口，除非产品已有可复用入口。

### 5.2 Apple 原生感与信息层级候选

- 推荐信息顺序为“现在是什么情况 → 为什么 → 我接下来能做什么”；主卡与双环形成同一概览整体，手机上下排列，宽屏左右排列；不得借此删除已确认信息或擅自改变正式业务结构。
- 品牌个性集中在已确认梗文案、少量品牌色和关键反馈；避免厚投影、悬浮抬升、弹跳、过多渐变、彩色底托和卡片套卡片。
- 金额使用统一等宽数字与对齐方式，不增加字号档位；动态字体放大时允许换行和增高，不为满足固定字号而截断内容。
- 付款提交前不播放成功反馈；必须在确认保存并回读成功后反馈。数字变化与进度线同步，不逐项排队播放；骨架屏保持原布局，减少上下跳动。
- 现有项目 Lucide 20px/2px 规范可作为候选起点，但不等于本轮最终签认；不得新增 SF Symbols、第二套图标库、依赖或 Token。

### 5.3 移动端和短视口阻断项

- 真实 390×844 首屏须压缩无效留白和重复月份/层级，使第一个有效功能模块不再被推迟到约 1003px；不得靠缩字号、隐藏已确认数据或删除模块解决。
- 390×520、软键盘、日期弹层和动态字体必须有独立证据；金额字段、当前焦点和“确认付款”在键盘出现时必须可达。长截图不能替代真机或等效交互证据。
- 760、980/1000、1440 仍按本任务书既定容器和单列/双列规则验收；760–880 仅在备注宽度不足 240px 时降级三行，宽屏不得回退。

## 6. 验收标准与证据

### 6.3 文案/资产
